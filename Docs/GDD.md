| ✅ | реализовано и работает |
| 🟡 | реализовано частично или стоит заглушка |

Где что лежит: сценарии диалогов новой сборки — `Docs/Диалоги/Ночь_N/` (ночь 1 написана), демо — `Docs/Архив_демо/Сценарии/`; сценарии ночей новой сборки — `Docs/Расписание.xlsx` (лист «Ночь_1» заполнен), таблица мини-игры «Эфир» (заявки слушателей и т. д.) — `Docs/Broadcast.xlsx`, расписание ночей и скрытые шкалы **демо** — `Docs/Архив_демо/Расписание_oldversion.xlsx`, записи сессий разработки — `Docs/AI/`.

## СТРУКТУРА ДОКУМЕНТА

Документ разделён на независимые рабочие блоки, чтобы каждый участник команды открывал только ту часть, которая нужна ему в работе.

**00 — Общее описание.** Читать всей команде. Кратко объясняет, какую игру мы делаем, её core loop, основные дизайн-принципы и тональность.

**01 — Сюжет / персонажи / диалоги / события.** Для сценариста и геймдизайнера. Здесь хранится весь сюжетный контент, персонажи, их арки, диалоги, сюжетные события и последствия решений.

**02 — Gameplay / механики.** Для программиста и геймдизайнера. Здесь описано только то, что игрок реально может делать и что требуется реализовать кодом.

**03 — Структура ночей.** Для сценариста, геймдизайнера и программиста. Главный рабочий раздел, в котором по каждой смене указаны события, звонки, механики, мистические эпизоды и последствия.

**04 — Локация / 3D / пропсы.** Для 3D-художника и level designer. Список окружения, оборудования, мебели, интерактивных и декоративных предметов.

**05 — 2D / UI / печатные материалы.** Для 2D-художника и UI-дизайнера. Газеты, записки, экраны компьютера, наклейки, документы, этикетки, интерфейсы.

**06 — Audio / Music / Voice.** Для sound designer, композитора и сценариста. Звуки, музыка, реклама, джинглы, радиоэфир и озвучка.

**07 — Art / Atmosphere.** Для художников, lighting и sound designer. Визуальный язык, атмосфера, эпоха, контраст уюта и мистики.

**08 — Техническая структура.** Для программиста. Системы, данные, события, world state, флаги и сохранения.

**09 — Production / Scope.** Для всей команды. MVP, vertical slice, приоритеты, cut list и рабочая структура задач.

**10 — Рекомендации по работе с Git.** Для всей команды. Ежедневный цикл, слияние в `main`, приём Pull Request.

**11 — Справочные материалы.** Частоты приёмника и инструкция по добавлению моделей в сцену.

## 00 — ОБЩЕЕ ОПИСАНИЕ

### 00.1. High Concept

Игрок соглашается на неделю подменить друга Серёгу, ночного ведущего радиостанции **103 FM**. Радиоточка устроена прямо в квартире: студийный стол с микшером, кассетниками и микрофоном стоит в одной из комнат, а вокруг — обычное жильё с прихожей, кухней, спальней и лестничной площадкой за входной дверью. Работа кажется простой: ставить музыку, давать объявления, принимать звонки, ставить музыку, выходить в эфир, общаться с слушателями и иногда соседями.

Когда игрок приходит на первую смену, Серёги уже нет, но на месте остались его вещи: куртка, ключи, кассеты, записи. На стене висит карта города с четырьмя красными крестиками. Постепенно выясняется, что Серёга никуда не уезжал: он пошёл спасать **Алису** — девушку, которая три месяца назад поймала странную волну и оказалась «там», в другом мире. Теперь застрял и он сам.

Оборудование ловит то, чего ловить не должно: голос Алисы в помехах, записи Серёги на автоответчике, шифры в самых обычных объявлениях. За смены игрок выясняет, что случилось с Серёгой, как раз вмешиваясь в истории слушателей и соседей, и решает, кому верить, чьи просьбы выполнять и кого вытаскивать из разлома. Природу аномалии объяснять до конца не обязательно.

Полная игра рассчитана на **7 ночных смен**. Сейчас собран **вертикальный срез**: три ночи с законченной дугой (знакомство → расследование → финал), из них реализованы ночи 1 и 2. Подробности — в разделах 03 и 09.

### 00.2. Core Loop

Одна игровая смена строится по общей схеме: смена начинается в полночь (00:00), игрок приходит в студию, изучает обстановку и последствия предыдущей ночи, выходит в эфир, принимает звонки, открывает дверь гостям и работает с техникой. Время идёт **шагами по 30 минут**, и каждое событие привязано к отметке на игровых часах. В правом верхнем углу всегда висит список текущих задач: новая появляется в момент события, пропадает, как только игрок к ней приступил.

Между обязательными блоками есть свободные окна: можно осмотреть квартиру, карту, вещи Серёги, послушать радио, поиграть на гитаре. В течение ночи игрок делает выборы, меняющие скрытые шкалы сюжета, а в 05:00 «ложится спать». Сон — отдельная сцена-разговор; после неё начинается следующая ночь. Последствия решений копятся и проявляются в финале.

> **Core loop переделывается (решение 11.10.2026).** Описанная ниже схема — это loop демо. Он строится на расписании по часам и мини-игре «Эфир» как главной работе, и автору это не нравится. Цель — новый loop уровня Dispatch, Static Dread, Papers, Please:
>
> 1. Игрок как оператор радиоточки проходит интересную рабочую мини-игру.
> 2. Затем отвлекается на новые сообщения: ставит композицию, даёт объявление в эфир, в этот момент принимает сюжетный выбор (помочь одной стороне или другой).
> 3. Периодически приходят соседи и разговаривают с игроком.
> 4. Периодически в самой квартире происходит мистика: гаснет свет, искажаются предметы, появляется тёмная сущность. Без скримеров, но настораживающе.
>
> Мини-игра «Эфир» (02.3) остаётся только как отдельная небольшая головоломка. Новая механика эфира за столом — **02.22** (черновик под плейтест).

### 00.3. Главные дизайн-пиллары

**Работа на радио — настоящий gameplay.** Игрок действительно использует микшер, кассетник, плеер, телефон, радиоприёмник и компьютер, а не просто выбирает реплики в диалогах.

**Информация — главный ресурс.** Игрок узнаёт секреты людей, события прошлого и возможного будущего, после чего решает, кому передать эти знания и как ими воспользоваться. Самое обычное объявление может оказаться шифром.

**~~«Не та клавиша»~~ — снят (11.10.2026).** Тема джема была нужна только для джема и в полной игре не используется. Выбор «правильный не всегда хороший» остаётся как приём в сюжетных развилках, но не как пиллар.

**Скрытые последствия.** Выбор игрока двигает невидимые шкалы. Игрок видит только короткую надпись «Это будет иметь последствия» и не знает, что именно изменилось.

**Персонажи и последствия.** У людей вокруг свои линии: бабка Зина, полиция, слушатели в эфире, сантехник. Игрок может помогать им, мешать, скрывать информацию или вмешиваться в их судьбы.

**Уют + мистика.** Радиоточка должна быть местом, где приятно находиться: тёплый приглушённый свет, музыка, чай, бытовые предметы эпохи, спокойные разговоры и гул техники. Паранормальные события работают через контраст с этим уютом. Квартира не должна постепенно превращаться в типичный хоррор-интерьер.

### 00.4. Кошка

Кошка — атмосферный элемент, у которого есть и сюжетная роль. Она приходит под дверь в ночь 1 в 04:00, и игрок решает, впускать ли её. Впустил — она живёт в квартире: бродит по комнатам, сидит и ложится. Пришла «оттуда», через разлом, и в финале может помочь спасти обоих — Серёгу и Алису. Сложного AI у кошки нет: она выбирает случайную точку на полу и идёт к ней по NavMesh. Механика голода и кормления описана в 02.13, пока не реализована.

### 00.5. Жанровое видение и референс

> Решение автора от 11.10.2026 (интервью по GDD, вопрос 1). Раньше жанровая смесь была без приоритетов.

**Референс — Static Dread.** Игра одновременно нарративный work-симулятор и визуальная новелла: вайб уютной постсоветской квартиры 90-х — 2000-х в России, работа на радио, разговоры.

**Контраст как основной приём.** Внутри помещение уютное, а то, что приходит снаружи (персонажи, звонки, события), подозрительное и неуютное; мистика хтоническая.

**Страх только через нарратив.** Скримеров и классического хоррора нет. Пугают отдельные моменты и события, их смысл, а не внезапный звук или картинка.

**Две части сюжета с разной механикой:**

| Часть | Как проходится |
|---|---|
| Нарративные ветки (Зина и криминал, полиция, культ, Алиса) | Выборами игрока и скрытыми шкалами (01.6) |
| Ветка Серёги | Головоломками. Это скрытая дополнительная концовка: основная масса пазлов игры принадлежит ей |

**Эмоция финала (вопрос 2).** Если игрок дошёл до настоящего финала и спас Алису или Серёгу, он получает облегчение. Тональный ориентир для сюжета — сериал «Очень странные дела».

**Структура концовок (предварительно).** Концовок много, и большинство негативные:

- Если отношения игрока с одной из противоборствующих сторон (шкалы 01.6) выведены в максимальный плюс или максимальный минус, игра заканчивается негативной концовкой по краю шкалы (01.7, «перебрал»).
- Если игрок удержал баланс и дошёл до конца, он спасает Алису или Серёгу — это «хорошие» концовки с облегчением.

> Открытое: ветка Серёги сейчас в GDD — один из полюсов шкалы `GirlFriend` (Серёга ⟷ Алиса). Если она становится скрытой концовкой через пазлы, нужно решить, как шкала и пазлы соотносятся (вопросы 17–18 интервью).

### 00.6. Устройство нового core loop (набросок)

> Решение автора от 12.10.2026 (вопрос 7). Это принципы; механика эфира за столом — 02.22 (черновик под плейтест). Core loop прорабатывается раньше остальных механик.

**1. Основной цикл обязателен, свободы выбора «чем заняться» нет.** Мини-игры эфира, звонки, разговоры с соседями — это ход ночи. Игрок не решает, делать ли их. Выбор происходит **внутри** них: какую музыку поставить, какое объявление дать в эфир, что ответить, какую сторону поддержать.

**2. Свободное время — для объектов квартиры.** Между событиями игрок может осматривать предметы: часть с головоломками, часть только на атмосферу. Это необязательно и доступно в любой момент вне основного цикла.

**3. Два вида событий в основном цикле:**

| Вид | Когда | Что даёт |
|---|---|---|
| **Сюжетные** — ключевые персонажи и диалоги | Строго по расписанию ночи | Двигают сюжет вперёд |
| **Случайные** — звонки слушателей, визиты части соседей | В свободные окна расписания, выбираются случайно | Не влияют на основной сюжет, но меняют отношения игрока с фракциями |

Так разнообразнее геймплей и дешевле разработка: случайные мини-встречи делаются из общего набора и не требуют отдельной сцены в каждой ночи.

**4. Отношения с фракциями.** Каждая встреча (в том числе случайная) двигает отношения с фракцией (шкалы 01.6). Если отношения выведены в максимальный плюс или минус, игрока ждёт негативная концовка этой фракции (00.5, 01.7).

**5. Давление.** Постоянного таймера нет. Давление добавляется точечно в отдельных сюжетных моментах: ограниченное время на выбор, «успел — опоздал». Где именно, решается для каждого момента отдельно.

**6. Ресурсы персонажа и кошки.**

- **Голод кошки** (`CatHunger`, 02.13) — за ним надо следить.
- **Усталость / сонливость и рассудок игрока** — новая механика: время от времени приходится отвлекаться от основного цикла, например выпить кофе, чтобы персонаж не заснул. Детали не определены: что происходит при полной усталости, чем восстанавливается, влияет ли на мистику.

**Показатели и время — гибрид (решение от 12.10.2026, вопросы 8–9).**

- **Усталость, рассудок, голод кошки** ухудшаются по **игровым часам** (например, −N за каждые 30 минут игрового времени) и восполняются действиями (кофе, корм и т. п.). Так они не наказывают за чтение диалогов и согласуются с 02.2: пока часы стоят, показатели тоже стоят.
- **Мини-ивенты квартиры — по реальному таймеру.** Если игрок какое-то время не разговаривает с персонажами и не работает за микшером, а ходит по квартире, реальный таймер периодически запускает мелкие события: гаснет свет, появляются мистические анимации и т. п. Это даёт жизнь свободному времени, не трогая показатели.

> Предложение, не решено: рассудок может меняться ещё и от событий (мистика, страшный звонок — минус; кофе, кошка — плюс), чтобы он был связан с сюжетом, а не только с часами.

**7. Баланс времени (ориентир).**

| Доля | Что делает игрок |
|---|---|
| ~50% | Рабочие мини-игры за микшером, чередующиеся с выборами за микшером (музыка, объявления, поддержка стороны) |
| ~25% | Встречи с соседями и гостями, случайные события |
| ~25% | Хождение по квартире: мистические события (гаснет свет, нужно что-то прибрать), покормить кошку, выпить кофе, осмотр предметов |

Образец структуры — Static Dread: управление радиоточкой перемежается разговорами и хождением по дому, где при определённых событиях появляется мистика (например, нужно дойти до двери, чтобы встретить гостя).

**Ритм ночи — синусоида напряжения (14.10.2026).** Спокойный быт и рутина чередуются с тревожными моментами: аномалиями в квартире, мистическими диалогами, неожиданными гостями. Подробнее — 01.1а.

**8. Ветвление и повторное прохождение (решение от 12.10.2026, вопрос 11).** Сюжет древовидный, как в визуальной новелле:

- **Каркас общий.** Ключевые события и диалоги стоят на своих местах в каждом прохождении.
- **Выборы включают будущие события.** Реплика, сказанная персонажу в одной ночи, может активировать отдельное событие в следующих ночах.
- **Случайные встречи против рутины.** Слабо влияют на сюжет, но двигают отношения с фракциями (пункт 3). Среди них могут быть и полезные встречи: торговец, информатор и т. п.

**9. Сон в конце ночи (решение от 12.10.2026, вопрос 12).** Сон — не обязательный ритуал, он бывает не каждую ночь. Будет ли сон и какой, решают выборы за ночь: помог Алисе — в конце ночи сон, связанный с ней; помог потусторонним силам — сон, связанный с ними.

**Усталость и досрочный сон — продумать.** Возможный вариант: если игрок не следит за усталостью, персонаж засыпает раньше положенного. Жёсткое условие: досрочный сон **не должен** пропускать ключевые события, которые ставят сюжетные флаги для следующих ночей. Способы, которые стоит рассмотреть: засыпание только в свободных окнах, а не перед сюжетной сценой; сон «на пару часов» с пробуждением от звонка или стука, после чего ключевое событие всё равно случается; при засыпании пропускаются только случайные встречи, а сюжетные переносятся.

> Открытое: что дают «полезные» встречи (предметы, подсказки к пазлам ветки Серёги, сведения о фракциях) и есть ли в игре что-то вроде денег или инвентаря для торговца.

### 01.1. Основной сюжет

Серёга просит игрока подменить его на неделю и говорит, что уезжает отдыхать. Игрок приходит в квартиру с радиоточкой — Серёги нет, вещи на месте. На стене карта города с четырьмя красными крестиками:

1. Радиовышка
2. Водонапорная башня
3. Старая обсерватория
4. Лесная трасса, 46-й км — **верная точка**

По ходу ночей игрок получает улики, и неподходящие точки зачёркиваются. Улики дают автоответчик Серёги, сантехник дядя Коля, сторож обсерватории Пётр Ильич, дальнобойщик Саша (лось на 46-м километре — первая, незаметная подсказка) и заметка в компьютере.

Параллельно идёт линия **бабки Зины**: она тайная связная бандитов. Её «объявления про кота / котят / гараж» — шифр: номер телефона в тексте — это время встречи (03 20 00 → 3:20, 04 00 00 → 4:00, 05 00 00 → 5:00). В последнюю ночь среза игрок слышит в волне спорящие голоса Серёги и Алисы (вытащить можно только одного), в 05:00 проверяются шкалы — не удержал баланс, за ним приходят, — и, если всё в порядке, он берёт радио (и, может быть, кошку) и едет на точку.

**Хтонь и квартира (шаг 2, решение от 14.10.2026).**

- **Правила.** Хтонь входит в квартиру, только если игрок сам её впустил: открыл дверь не тому, ответил не на тот звонок, поставил в эфир не ту запись. Как протоколы в Static Dread. Правила игрок узнаёт из записок Серёги, от «Политеха», от звонящих; часть правил ложная — их порождает апофения, и игрок не знает, каким верить. Нарушение впускает Хтонь, а впущенная Хтонь повышает счётчик.
- **Квартира остаётся уютной всю игру.** Счётчик Хтони не превращает её в хоррор-интерьер и не создаёт постоянного фона: он делает **эпизоды** аномалий чаще и сильнее. Аномалия — это тревожный, пугающий момент, после которого снова наступает быт.

**Последствия впущенной Хтони (шаг 3, решение от 14.10.2026).** Сила последствия растёт с тяжестью нарушения:

| Нарушение (пример) | Последствие |
|---|---|
| Мелкое: открыл дверь не тому | **Лично игрок:** падает рассудок, иногда растёт усталость; короткая аномалия в квартире |
| Тяжёлое: выпустил Хтонь в эфир | Плюс **мир и люди:** на следующую ночь что-то случается с кем-то из мини-веток (слушатель перестаёт звонить, у соседа «не те глаза», продавщица рассказывает о странном случае); счётчик Хтони сильно растёт |

**Хтонь не ломает работу за микшером.** Она не вызывает сбоев техники и не снижает качество эфира и зарплату. Но в работу может приходить мистический **контент**: странные кассеты, объявления, звонки (как разговор в эфире с дальнобойщиком Сашей в демо).

**Синусоида напряжения (принцип всей игры).** Спокойный быт и рутина перемежаются с тревожными аномалиями и мистическими диалогами. В дверь может постучать сосед по бытовому делу, бандит по своим делам или мистическая сущность — игрок не знает заранее. Обыденность и уют чередуются с напряжением от гостей, информации, аномалий в доме.

**Апофения против Хтони.** Апофения — то, во что верит много людей, но чего на самом деле нет и что не несёт реальной угрозы (верящие могут считать иначе). Хтонь — наоборот: настоящая угроза, в которую почти не верят. Апофения с двумя плохими краями: высокая — город в панике ищет виноватых и находит ночного ведущего с «голосами в эфире»; низкая — город не замечает реальную Хтонь, и та растёт. Радиолюбители «Политеха» тянут апофению вниз.

**Алиса (14.10.2026).** Существо из Изнанки взяло внешность и поведение настоящей Алисы. Открытое: возможно, настоящую Алису игрок встретит во второй половине игры.

**Настоящая Алиса — «дочь сотрудника» (16.10.2026, предварительно, ⚠️ вернуться и подумать позже).** Алиса — дочь учёного с объекта, которого не стало в ночь аварии (он среди «Отпечатков», 01.9). Она пришла с чертежами отца к Северу в «Политех», вместе с ним и Серёгой искала лабораторию, а потом пошла на склад одна и открыла вход (переписано 22.10.2026, подробно — `Скелет_ночей.md`, «Что было до игры»). Сущность Изнанки взяла облик Алисы, когда та была у разлома. **Сама Алиса в Изнанку не попала — она осталась в нашем мире**; её история развивается как побочная. Полиция ищет её как пропавшую. **Серёга (16.10.2026, вопрос 13; переписано 22.10.2026).** Алиса пришла к Северу с чертежами отца; Север позвал Серёгу; замерами сигнала по городу (крестики на карте) они вышли на заброшенный военный склад над лабораторией; там Серёга таскал армейские аптечки для бандитов. Он не знал, с какой мощностью и в каком радиусе действует проход, — и его случайно затянуло в Изнанку. Как вернуться обратно, он не знает.

### 01.4. Правила диалогов

Диалоги должны звучать бытово и естественно, без длинных литературных объяснений мистики. Игрок может выбрать реплику, промолчать, отключить звонок, вывести человека в эфир, записать разговор или выполнить действие оборудованием вместо ответа.

Пример правильного тона:

> — Ты вчера после трёх что-нибудь ловил?
>
> — В смысле?
>
> — Да ладно. Забей.

Практические правила записи в проекте (технический формат — в `Yarn/*.yarn`, см. раздел 08):

- Игрок подписывается «Я». Реплика-мысль без собеседника — просто «Я:».
- Перед каждым списком вариантов должна стоять реплика: без неё окно выбора показывает заглушку.
- **Выбранная реплика не дублируется** (решение автора, 18.10.2026): игрок уже прочитал вариант ответа, поэтому после выбора тот же текст ещё раз в окне диалога не показывается. ✅ Сделано (18.10.2026): настройка Yarn `runSelectedOptionAsLine` выключена, а в новых Yarn тело варианта начинается с ответа собеседника, без повтора. **Двоеточие в ремарке** пишется `\:` — иначе Yarn принимает текст до него за имя говорящего.
- Выбор можно делать тайно для игрока: параметры сюжета меняются прямо в тексте узла, игрок видит только «Это будет иметь последствия».

### 01.6. Скрытые шкалы сюжета

**Целевая схема — гибрид (решение от 14.10.2026).** Заменяет схему демо ниже.

| Вид | Показатель | Как работает |
|---|---|---|
| **Оси давления** (от минуса до плюса, старт 0) | **Криминал ⟷ Полиция** | Край в любую сторону → досрочная плохая концовка, проверяется в конце ночи (01.7) |
| | **Апофения** | Высокая — город в панике ищет виноватых; низкая — город не замечает реальную Хтонь (01.1а) |
| **Счётчики** (от 0 вверх) | **Хтонь** | Накопление угрозы от решений и бездействия |
| | **«Политех»** (радиолюбители) | Отношения: высокое доверие даёт помощь по ветке лаборатории и сдерживает апофению |
| | **«Гараж»** (рок-клуб) | Отношения: высокое доверие даёт помощь, вплоть до защиты от бандитов |

**Как игрок узнаёт о своём положении.** Шкалы по-прежнему не показываются цифрами. Положение видно косвенно, через мир: сплетни продавщицы ларька, звонки в эфир, новости по приёмнику, то, как с игроком разговаривают.

**Финал.** Основная развязка — ветка Алисы и Серёги; к ней добавляются эпилоги по каждой оси и счётчику («город погрузился в Хтонь», «бандитов поймали» и т. п.).

**Открытое:** диапазон осей (в коде сейчас ±5, обсуждался вариант ±10, как в Reigns); есть ли у счётчика Хтони порог, ведущий к плохой концовке; дают ли низкие значения «Политеха» и «Гаража» что-то кроме отсутствия помощи; устройство показателя Алисы и Серёги.

Три шкалы с диапазоном **от −5 до +5** (старт 0) и одна от 0 до 100. Игрок их не видит.

| Параметр | Что означает | Знак |
|---|---|---|
| `Crime` | ⚖️ Полиция ⟷ Криминал | **+** к криминалу, **−** к полиции |
| `Cult` | 🐙 Культ | **+** культ, **−** против культа |

### 01.7. Концовки

**Принцип неудачи (решение от 12.10.2026, вопрос 10).** Неудача не должна душить игрока. Кто играет стабильно, спокойно проходит все ночи и в конце получает концовку по своим решениям, как в визуальной новелле. Промежуточные (досрочные) концовки получает только тот, кто играет совсем плохо или намеренно всё рушит, например всё время мешает одной фракции. Такие концовки проверяются **в конце ночи**, а не в момент выбора.

**Финальная развилка — дилемма вагонетки (решение от 16.10.2026, вопрос 18).** Выбор должен быть тяжёлым моральным решением, а не лёгким выбором «кого спасать».

- **Сущность-Алиса не раскрывается в лоб.** Игроку не говорят, что она поддельная: она ведёт себя как настоящая пропавшая Алиса, которая застряла в Изнанке и просит помочь.
- **Линия Алисы — романтическая, с потусторонним персонажем, и развивается плавно:** знакомство, общение на отвлечённые темы, прогулки во снах; Алиса располагает игрока к доверию. Если игрок поддерживает её ветку, он выходит на возможность вытащить её из Изнанки.
- **Альтернатива — вытащить Серёгу**, друга.

| Концовка | Что происходит | Статус |
|---|---|---|
| Спасти Серёгу | Алиса остаётся в Изнанке | Решено |
| Спасти Алису | Серёга остаётся в Изнанке | Решено |
| **Самопожертвование** («средняя») | Игрок жертвует собой и помогает обоим — Серёге и сущности-Алисе | Решено |
| Хорошая концовка через головоломки | Пазлы ветки Серёги позволяют помочь всем | Подумать |
| **Секретная: настоящая Алиса** | Пазлы выводят на настоящую Алису (01.1а) | Подумать |

Плюс досрочные концовки «перебрал» по осям давления (ниже).

**Уточнения (16.10.2026).**

- **Открытый финал.** В конце игрок узнаёт, что Алиса — существо, обитавшее в Изнанке. Злая она или нет, в лоб не говорится: игрок сам решает, испытывала ли она чувства к герою или герой был для неё только способом выбраться.
- **Вес Серёги.** Чтобы дилемма была тяжёлой, у Серёги должно быть больше присутствия: свидетели и то, что связывает мир с ним (Север, который чувствует вину, Викторыч, «Гараж»), его исчезновение — потеря для других персонажей, а не только для игрока. Как сделать выбор действительно тяжёлым — ещё продумать.
- **Правило обмена** (чтобы кто-то вышел из Изнанки, кто-то должен остаться; объясняет все три основных финала, включая самопожертвование) — возможный вариант, подумать.
- **Головоломки:** через них игрок либо узнаёт правду о сущности-Алисе, либо знакомится с настоящей Алисой, либо и то и другое — проработать позже.
- **Настоящая Алиса** — возможно, вводится ближе к финалу как альтернативная романтическая линия. Проработать позже.
- **Ветки Серёги и Алисы поначалу не пересекаются.** Игрок не знает, что такое Изнанка, и узнаёт факты постепенно. Реплику Серёги «не слушай Алису» из сценария **убрать** (сейчас она есть в автоответчике ночи 2, `020007`, и в 01.2).

**Концовка «перебрал» — целевая схема.** Досрочные концовки бывают только у **осей давления** (01.6): Криминал ⟷ Полиция и Апофения — по концовке на каждый край, четыре в сумме. У счётчиков плохих краёв нет (порог Хтони — открытый вопрос). Названия и сцены концовок — TBD.

**Концовка «перебрал» — как в демо (в разработке).** Если параметр дошёл до края шкалы, игра заканчивается в конце этой ночи (раньше в демо — сразу; меняется по принципу выше): шесть концовок по краям — Соучастник (`Crime` максимум), Бабка Зина (`Crime` минимум), Искажение (`Cult` максимум), Ритуал (`Cult` минимум), Алиса (`GirlFriend` максимум), Серёга (`GirlFriend` минимум). Сейчас вместо сцен стоят заглушки с названием на чёрном экране, и срабатывание **выключено**.

**Концовки финала среза (ночь 3, пока только в сценарии).** Порядок проверки в 05:00: сдал Зину или полиция слишком «громко» → «Бабка Зина»; «Соучастник»; «Ритуал». Иначе игрок едет к точке: неверная точка → «Пустой эфир»; верная + кошка → «Оба»; верная без кошки → громче тот голос, к кому ближе `GirlFriend` (при 0 — Серёга). Дополнительные эпилоги города («Искажение», «Полиция накрыла банду», «Зина держит район») — в таблице.

> Открытый вопрос: пороги концовок в `Docs/Архив_демо/Расписание_oldversion.xlsx` (например ⚖️ ≥ 7) рассчитаны на более широкую шкалу, чем принятые в игре ±5. Прежде чем реализовывать финал, пороги нужно пересчитать.

### 01.8. Улики и объекты осмотра

Предметы, которые игрок осматривает по дороге и которые двигают сюжет или создают настроение:

- **Карта города** на стене студии — осмотр с репликой «Серёга что-то отмечал… Может, он поехал в одно из этих мест?». Крестики зачёркиваются по ходу ночей.
  - **Смысл карты в новом сюжете (решение автора, 17.10.2026).** Крестики — места, где, по расчётам Серёги, должен ловиться сигнал. В одном из них сигнал Изнанки действительно ловится: под землёй там лаборатория. Улики вычёркивают ложные точки (головоломка ветки Серёги).
  - **На подумать.** На карте могут появляться и другие отметки — места, куда можно «съездить»: перемещение на маленькую локацию или показ другой локации как диалога на другом фоне (как в визуальной новелле). Например, отметки по звонкам слушателей о помехах и Хтони.
- **Куртка Серёги** у входа — осматривается один раз.
- **Банка квашеной капусты** от бабки Зины — появляется на столе в 01:00, осматривается один раз.
- **Записки и граффити.** Записка с шифром, записка с морзянкой («3D просмотр» без вращения), граффити на стене подъезда («Цой жив», «103.1», «возьми кошку с собой» мелко в углу). ⚠️ Надпись «103.1» устарела (частота убрана, 11.1) — заменить или убрать из текстуры.
- **Кодовый замок** `Zamok1` на двери: три цилиндра с цифрами, верный код **404** открывает дверь.
- **Заметка №1** в компьютере (раздел «Файлы», под паролем «не спи»): «Учётная запись: Сергей. Водонапорная башня — не подходит, сигнал там почти не ловит».
- **Гитара** — запускает мини-игру «Гитара» (02.15), к сюжету не привязана.

## 02 — GAMEPLAY / МЕХАНИКИ

Этот раздел содержит только игровые системы, которые требуют реализации. У каждой указан статус: ✅ реализовано, 🟡 реализовано частично или с заглушкой, ⬜ не реализовано.

### 02.1. Interaction System — ✅

Игрок смотрит на объекты, нажимает кнопки, берёт предметы, рассматривает их вблизи, использует телефон, радио, компьютер и замок.

- **Прицел** в центре экрана: в покое точка, при наведении на интерактивный объект она разрастается в кольцо, а сам объект обводится белой каймой. Все три реакции зависят от одного и того же условия, поэтому разойтись не могут.
- **Взаимодействие — клавиша F.** Вторая подсказка управления постоянно висит в правом нижнем углу: «F — Взаимодействие / Отмена».
- **Радиус взаимодействия** у каждого объекта свой; за пределами радиуса объект не подсвечивается.
- **Режим за столом.** Игрок садится в кресло (F), курсор освобождается, предметы выбираются мышью (тонкая обводка), клик взаимодействует. Взгляд поворачивается между двумя половинами углового стола: стрелками на краях экрана или клавишами **Q / E** (подписи Q и E стоят над стрелками). Приборы на столе работают **только** сидя: на подходе они не подсвечиваются.
- **«3D просмотр»** — предмет можно взять: он подлетает к камере, зажатой кнопкой мыши вращается, клавиша выхода кладёт обратно. Без вращения работают записки, карта. Перед просмотром может прозвучать реплика.
- **Дверь.** Нажатие на входную дверь включает отдельную камеру, смотрящую на лестничную площадку, дверь открывается, курсор свободен — гости видны в дверном проёме и с ними можно говорить мышью. Повторное нажатие закрывает дверь.
- **Компьютер.** Камера подъезжает к монитору, на месте стекла включается мировой холст (см. 02.16).
- **Приёмник.** Игрок встаёт перед радио, камера смотрит на шкалу (см. 02.8).
- **Совместная приостановка.** Управление игроком останавливают сразу несколько систем (кресло, диалог, мини-игра, просмотр). Приостановка ведётся счётчиком владельцев: отпускать управление должен каждый, кто его забрал, поэтому закрытый за столом разговор не поднимает игрока из кресла.

### 02.2. Time System — ✅

Смена длится с 00:00 до 06:00 (360 минут). Игровое время продвигается **только от действий игрока**: победа в мини-игре, конец разговора, сюжетное взаимодействие — всегда в явно указанную отметку или на явно указанный сдвиг. Пока игрок осматривает квартиру или думает, часы стоят. Обычные бытовые взаимодействия время не двигают.

- **Шаг времени — 30 минут** (сдвиги 30 / 60 / 90 / 120). Время двигается командами диалога `advance_time` и `advance_time_to`.
- **Номер ночи** входит в отметку: формат «ЧЧ:ММ:НН», где НН — номер ночи (`01:00:02` — час второй ночи). Для ночи 1 допустима запись без номера.
- **Все события привязаны к игровым часам.** Событие — это отметка на часах плюс (при необходимости) задержка в **реальных секундах** после того, как часы до отметки дошли. Это нужно тем событиям, которые не должны срабатывать в тот же кадр: телефон звонит через пару секунд после начала ночи. Привязки только к реальным секундам от загрузки сцены нет.
- **Часы смены** показываются на панели задач компьютера.
- **Отладка.** Правый Ctrl открывает сводку (только редактор и отладочная сборка): значения параметров сюжета и `GameTime: ЧЧ:ММ [ночь N, M / 360 мин]`. Пока она открыта, четыре цифры подряд ставят время текущей ночи (`0130` = 01:30), шесть цифр `ЧЧММНН` — любую ночь. При переводе вперёд все события и задачи раньше введённой отметки считаются пройденными: срабатывают только события этого времени и позже, звонящий телефон глушится.

### 02.3. Broadcast Schedule и мини-игра «Провода» (бывший «Эфир») — ✅ не запускается

> **Роль меняется (11.10.2026).** «Эфир» перестаёт быть core loop и остаётся отдельной небольшой головоломкой — пока назначен на ремонт (02.22). Новый core loop — 02.22. Описание ниже — как работает в демо.
>
> **17.10.2026: переименована в «Провода».** Название «Эфир» теперь у эфира за столом (02.22): «Начать эфир» на микшере открывает его во всех эфирах ночей 1 и 2. «Провода» нигде не запускаются, но код и префаб `WirePuzzle` остаются — мини-игре ищут другое применение. В списке запусков `MinigameHost` у каждого эфира есть поле «Что запускать»: эфир за столом или «Провода».

Эфирная сетка состоит из музыки, рекламы, новостей, объявлений и разговорных блоков. В текущей реализации «выход в эфир» — это мини-игра **«Эфир»** (внутри кода — «Провод»).

**Как запускается.** На микшере в диалоге есть вариант «Начать эфир»; он открыт, только если по часам есть непройденный эфир. Какой именно эфир идёт сейчас, игра выбирает сама: в ночи 1 — с 00:00 и с 02:00, в ночи 2 — с 00:30, с 02:00 и с 03:30.

**Правила.** Поле мини-игры повторяет раскладку клавиатуры: четыре ряда клеток, расположение которых совпадает с расположением клавиш (клавиши позиционные — ЙЦУКЕН и QWERTY работают одинаково). На поле еле заметно нарисована раскладка и по проводу бежит маячок сигнала (иконка микрофона). Когда маячок добегает до **узла** провода, нужно нажать клавишу, стоящую на этом месте. Маячок на узле не останавливается: нажать нужно в окне вокруг момента прохождения. Нажал рано, не ту или не успел — провал, и уровень начинается заново. Выйти можно, только пройдя.

**Сложность.** Провод каждый раз собирается случайно под заданные число клавиш и скорость (стартовое задание: **5 клавиш, скорость 2**; второй уровень — скорость 3). Генератор не повторяет клавиши, не ставит узлы вплотную и не выстраивает три узла на одной прямой. Эфир может состоять из нескольких уровней подряд: поле между ними не закрывается, музыка не прерывается.

**Звук и обратная связь.** Пока открыто поле, играет случайная музыка из папки `Audio/Efir`, доиграла — следующая. Любое нажатие клавиши — звук `EfirTap1`, засчитанное нажатие — `EfirTap2`; иконка микрофона на нажатие коротко сжимается и возвращается. Громкость — 50%.

**После победы** ставится флаг эфира, задача снимается и часы переходят на отметку, заданную для этого эфира (например, первый эфир ночи 1 — 00:30).

### 02.4. Mixer — 🟡

Основные источники: MIC, PHONE, TAPE A, TAPE B, CD, AUX, LINE. Микшер — прибор за столом; по клику открывается диалог со списком каналов.

- ✅ **TAPE A** — запускает короткую запись `103FM` (на 50% громкости, ~11 секунд); пока она играет, остальные варианты погашены и возвращаются сами, когда запись кончилась. Выбор канала снимает задачу «Включить Tape A» и ставит «Начать эфир».
- ✅ **PHONE** — в ночь 2 (03:30) ведёт на звонок в эфир (Тамарочка).
- ✅ **Начать эфир** — запуск эфира за столом (02.22; раньше — мини-игра «Провода», 02.3).
- ⬜ Остальные каналы (MIC, TAPE B, CD, AUX, LINE) — заглушка: канал щёлкает, но в эфир пока выводить нечего. Включение и выключение каналов, громкость, вывод в эфир / монитор / запись не реализованы.

**Микрофон** отдельно: нажатие на него в нужный момент открывает «выход в эфир» с диалогом (приветствие ведущего, затем выбор объявления или песни). Над стеной загорается табличка «В ЭФИРЕ».

### 02.5. Cassette System — 🟡

Кассета — физический предмет с параметрами ID, название, содержимое, длительность, возможность перезаписи, признак «сюжетная / обычная». Как система предметов пока не реализована.

Реализованы **проигрыватели**: плеер (`Pleer`) ставит выбранную кассету, кассетник микшера играет запись `103FM`. Играет она в сцене как звук от самого прибора, песню можно заглушить. В ночи 1 в 03:30 игрок выбирает одну из трёх песен («На языке, на котором я вижу сны», «Эй ковбой», «Ты потеряла путь среди чужих огней»), каждая двигает свою шкалу (02.9 / 01.6).

### 02.6. Phone System — 🟡

Телефон на столе доступен всегда. Что окажется в трубке, решает диалог (`Phone.yarn`): по ночи, времени и флагам он выбирает звонок или, если никто не звонит, гудки («Телефонные гудки…»).

- ✅ **Входящие по часам.** Звонок — отметка на часах плюс задержка в реальных секундах. Каждый звонок тянется со звуком, пока игрок не снимет трубку (клик в режиме за столом).
- ✅ **Перезвон по просьбе диалога.** Диалог может попросить телефон зазвонить через N реальных секунд.
- ✅ **Автоответчик Серёги** (ночь 2) слушается через телефон; мини-игры с ползунками нет.
- ⬜ Принять, сбросить, удерживать линию, вывести в эфир, записать разговор, переключить линию — как отдельные действия не реализованы. Звонок «в эфир» (Саша, Тамарочка) идёт как обычный диалог.

### 02.7. Dialogue System — ✅

Диалоги написаны на **Yarn Spinner** (обычные текстовые файлы `.yarn`, которые правятся в любом редакторе). Игровое состояние и переменные диалога — одно и то же: флаги мира и часы читаются прямо из игры.

- **Внешний вид.** Диалоговое окно по центру экрана: сверху имя говорящего, затем реплика с печатью по буквам, затем варианты. Заданные вопросы остаются в списке зачёркнутыми, а не пропадают. Белая стрелка для продолжения увеличена, чтобы по ней было проще попасть. Реплики без выбора листаются кликом по тексту или пробелом; Esc пропускает реплику.
- **Собеседник на экране.** Если у говорящего есть портрет, анимированный персонаж встаёт по центру кадра, а окно диалога переезжает в правую половину экрана. Сейчас портрет есть только у бабки Зины (видео с прозрачным фоном).
- **Условия.** Реплики и варианты появляются по флагам, времени, ночи и параметрам. Объект может «молчать» (не быть доступным), пока условие не выполнено.
- **Команды в игру**: смещение времени, запуск мини-игры, постановка и снятие задач, свет «В ЭФИРЕ», запуск кассеты, ввод числа игроком, показ собеседника, сон, перезвон, радио.
- **Ввод числа.** Диалог может попросить набрать число с клавиатуры (например, номер объявления бабки Зины: 032000).
- **Стадия.** Диалог может включать и выключать предметы в кадре.
- ⬜ **Таймер ответа и «молчание»** — не реализованы.
- ⬜ **Дрожащий текст** реплики и нагнетающая музыка под реплику — нужны для Дежурного (01.9, решение автора 21.10.2026).
- ⬜ **Озвучка** — не реализована; уникальные ID реплик Yarn расставляет сам.

### 02.8. Radio Frequency System — 🟡

Радиоприёмник — интерактивный объект. При взаимодействии игрок встаёт перед ним, камера смотрит на экран со шкалой частот. **Q / E** крутят ручку (анимация), частота бежит по шкале, цифры текущей частоты показаны на экране. Диапазон **87,5–108 МГц**.

- **R** включает и выключает радио — и в режиме настройки, и просто навёдшись на приёмник в 3D.
- Включённое радио **продолжает играть**, даже если игрок ушёл от него. Пока включено, между станциями слышны помехи. Чем ближе к частоте станции, тем тише помехи и громче станция; точно на частоте помех нет. Песни станции берутся случайно из её папки.
- **Станции:** Авторадио 90,3; Новости 91,2 (пока помехи); Серебряный дождь 100,1; Наше радио 101,7; Русское радио 105,7; Европа Плюс 106,2; **Морзе 94,0** (повторяющийся сигнал). Частота **103,0** — радиостанция самого игрока, её в эфир приёмника не отдаём; частота 103,1 из исходной концепции **убрана** (16.10.2026): слишком близко к частоте станции игрока, рядом с 103,0 ничего не ставим.
- **Голос на частоте.** Когда в сюжете появляется задача «подойти к радио», приёмник сам включается и шипит; на частоте **96,6 ± 0,3** начинается разговор с Алисой (ночь 2, 04:00). Срабатывает один раз.
- ⬜ Параметры gain и filter, определённые диапазоны, запускающие другие события, — не реализованы. Интерактив «Поймать волну» ночи 3 (крутить ручку, пока шум не станет голосами) — только в сценарии.

### 02.9. Wrong Combination System — ⬜

Система проверяет состояния нескольких устройств. Например: Frequency = 96.6, AUX = ON, TAPE_B = PLAY, MONITOR = ON → запускается специальное событие. Не реализована; опирается на каналы микшера, которых пока нет.

### 02.10. Recording System — ⬜

Игрок может записывать телефон, эфир или необычные сигналы. Запись становится новым состоянием кассеты или отдельным предметом. Не реализована.

### 02.11. World State — ✅

Флаги мира трёх типов (да/нет, число, строка); незаданный флаг читается как «пусто». Типы по соглашению: сюжетные (`STORY_FOUND_SERGEY_KEYS`), отношения с NPC (`NPC_MISHA_TRUST`), знания (`KNOW_ACCIDENT_DATE`), действия игрока (`ACTION_AIRED_WARNING`), секретные необязательные (`SECRET_CAT_HINT_01`) и состояние задач (`TASK_…`). Скрытые шкалы сюжета (01.6) — тоже числовые флаги. Любой диалог меняет их простым присваиванием.

### 02.12. Save System — ✅ (19.10.2026)

**Решения автора (19.10.2026):** одно автосохранение, ручного нет. «Продолжить» в меню грузит его; «Играть» при существующем сохранении сначала предупреждает («Сохранение будет перезаписано. Нажми ещё раз»). Отдельно пишется снимок начала каждой ночи (`night_<N>.json`) — задел под выбор ночи в меню.

**Когда сохраняется:**
- **начало ночи** — после пробуждения у дивана, до первых событий ночи; для новой игры — сразу при входе в квартиру;
- **после сюжетного шага** — когда ставится флаг завершения из `StoryBeats`. Сохранение ждёт спокойного момента: игрок не в разговоре, не за столом, не в мини-игре, телефон не звонит, не идёт сон или глюк коридора (`ISaveBlocker`), и так 1,5 с подряд. Внизу слева появляется «Сохранено».
- Отладка: правый Ctrl + S — сохранить сейчас.

**Что сохраняется** (`SaveData`, JSON в `Application.persistentDataPath`): часы и ночь; все флаги мира (шкалы, деньги, переменные Yarn, `TASK_*`); активные задачи в порядке появления; какие события по часам уже сработали (у каждого постоянный ключ — после загрузки звонок или стук не повторяется, а то, что ещё не наступило, наступит); где стоит игрок.

**Правило для объектов:** состояние объекта сцены хранится во флагах `OBJ_*` — объект пишет флаг при изменении и читает его по событию `GameSession.Restored`. Так сделаны радио (`OBJ_RADIO_ON`, `OBJ_RADIO_FREQ`), показ предметов из диалога (`OBJ_STAGE_<имя>`). Кодовый замок и дверь за ним выводятся из `ACTION_LOCK_OPENED`, вещи по времени (`ActivateAtTime`) — из часов, кошка — из флага. Новому объекту, чтобы сохраняться, сериализацию трогать не нужно.

**Не сохраняется намеренно:** середина событий (эфир, звонок, кассета) — в такой момент сохранения нет; где кошка и какой трек играет; осматриваемые предметы всегда возвращаются на место.

### 02.13. Ambient Interactions — 🟡

Некритические действия, существующие в первую очередь для атмосферы. Реализовано: осмотр куртки, банки, карты, записок и граффити; кодовый замок; гитара; кошка. **Кошка** ходит по квартире (NavMesh, случайные точки), сидит и ложится; на нажатие по ней говорит «Мяу». ⬜ Голод кошки: параметр `CatHunger` заведён, а задание «покормить кошку», шкала голода и корм на кухне — не реализованы. ⬜ Чайник, кружки, окно, журнал, телевизор — не реализованы.

### 02.14. Task System — ✅

Список текущих задач в правом верхнем углу, виден всегда: при ходьбе, за столом, в разговоре и в мини-игре. Новая строка проявляется, снятая — коротко гаснет. Задача появляется в момент события и исчезает, как только игрок к ней приступил (не когда выполнил). Ставит и снимает задачи сюжет командами диалога либо часы смены в нужную отметку; выполненная задача не возвращается. Тексты всех задач собраны в одном каталоге, а не разбросаны по диалогам.

### 02.15. Мини-игры

**«Эфир»** (эфир за столом) — см. 02.22. **«Провода»** (бывший «Эфир») — см. 02.3, сейчас не запускается.

**«Гитара»** (караоке-ритм) — ✅. Игрок берёт гитару, играет песня («Последний герой»), и на каждое слово нужно вовремя нажать его **первую букву**. Провала нет: песня идёт до конца, затем итог со счётом. Выйти можно в любой момент кликом мыши. Тайм-коды слов лежат отдельным файлом. К сюжету пока не привязана.

> Это первые из нескольких запланированных мини-игр; у каждой будет свой уровень сложности.

### 02.16. Компьютер — 🟡

На месте стекла монитора — рабочий стол со значками, окном программы, часами смены и кнопкой «Отойти от монитора». Значок без своей программы просто показывает текст.

- ✅ **Почта.** Письма — вкладки в списке «Входящие». Письмо появляется по флагу мира, поэтому сюжет «присылает» почту обычным флагом. Письмо полиции «РАЗЫСКИВАЕТСЯ ЧЕЛОВЕК» приходит в 01:00 ночи 1; прочтение ставит флаг знания и снимает задачу.
- ✅ **Файлы.** Записи, часть под паролем (регистр, пробелы, подчёркивания и «ё» не важны: «не спи», «неспи», «не_спи»). Открытая запись запоминается флагом.
- 🟡 Остальные значки (эфирная сетка, журнал смен, корзина) пока показывают текст-заглушку.

### 02.17. Гости и дверь — ✅

Гость приходит по часам: стучит ровно **два раза** — когда пришёл и когда игрок впервые встаёт из-за стола, — и ждёт. При приходе появляется задача «открыть дверь». Открыть дверь можно когда угодно. 3D-гость (кошка) стоит на площадке и начинает анимацию, когда дверь открывают. Гости ночи 1: бабка Зина (00:30), кошка (04:00); ночи 2: бабка Зина (01:30), сантехник (02:30).

### 02.18. Сон и смена ночей — ✅

После 05:00 на диване есть вариант «Лечь спать» (раньше — «Не время спать»). Экран темнеет, на чёрном фоне идёт разговор-сон (`NightN_Dream`; в ночи 1 на фоне видео), затем «Ночь N завершена», «Ночь N+1 / 00:00», игрок просыпается у дивана, звучит мысль («Ох… Серёга, он что, не вернулся?»), начинается следующая ночь.

### 02.19. Меню и вступление — ✅

Главное меню с видеофоном, случайной музыкой из папки с кассетами и стрелками «Переключить кассету». Кнопки: **Играть** (сначала вступительный ролик, потом сцена `Apartment`), **Продолжить** («Сохранения в разработке»), **Настройки** («Их нет»), **Не нажимать!** (случайная фраза), **Выход**. Справа внизу — предупреждение «Осторожно, в игре могут быть громкие звуки».

### 02.20. Локализация — ⬜

> Решение автора от 12.10.2026: игра будет переводиться на другие языки, поэтому локализация закладывается в разработку сразу, а не добавляется перед релизом.

**Язык оригинала — русский.** Диалоги пишутся в файлах Yarn Spinner (`.yarn`, 02.7); Yarn Spinner 3 поддерживает локализацию: у каждой реплики есть уникальный тег (`#line:…`), по ним строится таблица строк, которая переводится на другой язык и подгружается вместо оригинала.

**Что уже известно по проекту:**

- В имеющихся `.yarn` файлах (`Assets/_Project/Yarn`) тегов `#line:` пока нет: Yarn расставляет ID сам при компиляции, а для перевода нужны постоянные теги, записанные в файл. Их надо добавить (в Yarn Spinner для этого есть команда в редакторе) **до** того, как переводчикам отдадут тексты.
- Текст вне диалогов (задачи в `Data/Tasks.asset`, подсказки управления, меню, надписи «Это будет иметь последствия», «Ночь N», письма и файлы компьютера, записки, подписи предметов) зашит в данные и код. Его тоже нужно вынести в таблицы строк.
- Шрифт интерфейса `LiberationSans SDF RU` покрывает кириллицу и латиницу; для других алфавитов (например, китайского) потребуются отдельные шрифты.
- Картинки с текстом (записки, граффити, карта, газеты, этикетки кассет) и озвучка (06.8) локализуются отдельно: нужны версии под каждый язык либо оформление без надписей.

**Правила для авторов, чтобы не ломать перевод:** не склеивать фразы из кусков в коде; числа и имена подставлять через переменные Yarn; не вшивать русский текст в картинки без запасной версии; помнить, что в других языках текст длиннее, и оставлять запас под рамками.

**Открытое:** какие языки и в каком порядке (вопрос 6 интервью, ответа пока нет); переводят люди, переводчик или ИИ с вычиткой; нужна ли озвучка на других языках или только субтитры.

### 02.21. Мини-локации («провалы») — ⬜

> Задумка от 14.10.2026. Нужна для самых напряжённых хоррорных моментов; какие объекты её используют — бестиарий 01.9.

Игрок долго смотрит на объект с аномалией (рябящий ковёр, экран телевизора) → открывается взаимодействие → если согласиться, игрок ненадолго попадает в отдельную безумную локацию с коротким сюжетом: внутрь объекта или в Изнанку → затем возвращается в квартиру. Каждая мини-локация — отдельная небольшая сцена, поэтому их немного: только для избранной Хтони.

Открытое: можно ли в мини-локации проиграть или пострадать (рассудок, 00.6); двигают ли они игровые часы; отказ от взаимодействия — без последствий или тоже выбор.

#### 02.21а. Общее правило мини-локаций (решение автора, 18.10.2026)

- **Основная сцена с квартирой сохраняет весь прогресс** при переходе в мини-локацию и обратно: шкалы фракций, деньги, купленные предметы и где они стоят, перемещённые объекты, состояние каждого объекта и т. д.
- **Мини-локации эпизодические:** эпизод прошёл — игрок возвращается к основной игре.
- Принцип переиспользуется: сны с Алисой и часть мини-локаций Хтони (01.9) строятся одинаково.

> Держать квартиру загруженной под мини-локацией **не будем** (решение автора, 18.10.2026: вопрос оптимизации). Значит, состояние квартиры при переходе нужно **сохранять и восстанавливать** — это требование к системе сохранений (02.12).

> 19.10.2026, первая версия перехода (`MiniLocationTrip`): квартира выгружается, перед уходом запоминаются **часы и все флаги мира** (шкалы, деньги, переменные Yarn). При возвращении квартира грузится заново, на чёрном экране восстанавливаются часы и флаги. Теперь снимок для мини-локации — тот же, что у сохранения (02.12): часы, флаги, задачи, сработавшие события, объекты через флаги `OBJ_*`.
>
> Сон ночи 1: «Лечь спать» → сцена `Dream_N1` → жёлтая точка у колеса обозрения (временная, вместо забега) → квартира, на чёрном экране фраза Алисы (`Night1_DreamEnd`), титры, пробуждение во второй ночи. Сцена сна задаётся по ночам в `SleepSequence` → «Сцены сна»; без сцены сон идёт текстом (`Night{N}_Dream`).

#### 02.21б. Сон-Изнанка — ⬜ (решение автора, 18.10.2026)

Формат мини-локации для снов с Алисой (и, возможно, части хтонических эпизодов). Сны с Алисой возникают несколько раз за игру (когда — решают выборы, 00.6 п. 9).

**Визуальный язык.** Референс — киберпространство и Заслон в Cyberpunk 2077 (скриншоты автора 18.10.2026).

| Что | Как выглядит |
|---|---|
| Окружение | **Чёрное**, без внешних источников света |
| Все объекты и существа | Наборы **светящихся цветных точек и контуров** (облака точек, сканлайны, вертикальные «нити») |
| Объекты и существа **нашего мира** | **Голубоватые**: от бирюзового до холодного голубого (по референсу ≈ `#3FA9C9`–`#7FD3E6`) |
| Объекты и существа **Изнанки и Хтони** | **Красно-розовые**: от алого до малинового (по референсу ≈ `#FF2A55`–`#FF3FA0`) |
| Цели игрока (контрольные точки) | **Жёлтые** |
| Неправильные детали | Обычные пропсы нашего мира, неестественно висящие в воздухе; могут подсвечиваться красным |

**Погони (решение автора, 21.10.2026).** В сюжетно прописанных снах за героем гонится **Дежурный** (01.9): неестественно высокая красная фигура контролёра или консьержа. Платформинг по жёлтым точкам становится бегством.

**Цвет Алисы (решение автора, 18.10.2026).** Алиса светится **голубым**, как человек, — она маскируется. Но края её фигуры изредка вспыхивают красным: подсказку легко не заметить или списать на сон.

**Первый Сон-Изнанка (ночь 1).** С Алисой ещё **не общаемся**: герой стремится встретиться с ней и поговорить, а она ускользает. Окружение — парк с аттракционами и водоёмом. Алиса появляется и исчезает, зовя героя за собой; игрок бежит за ней по контрольным точкам: прошёл точку — Алиса появляется на следующей и зовёт дальше (бег-платформинг). **В конце сна** она говорит одну-единственную фразу — намёк, что сделать во вторую ночь (например, поставить в эфире её песню).

**Прогрессия.** От сна ко сну платформинг усложняется, игрок получает навыки. **Черновой порядок** (будем тестить и обсуждать): бег и прыжок → **двойной прыжок** → **рывок** → парение → «настройка» (💡: переключение между голубым и красным слоем мира, где твёрдыми становятся платформы только одного цвета — как поймать частоту). **Двойной прыжок точно открывается в первом сне, рывок — скорее всего тоже.**

**Открытое:**

- 💡 **Навыки и сюжет.** Каждый новый навык даёт Алиса — это стадия их сближения.
- 💡 **Сны условные** (бывают не каждую ночь), поэтому навыки привязываются к **номеру сна**, а не к номеру ночи; уровни строятся так, чтобы пропустивший сон не застрял.
- 💡 **Падение без наказания** в первых снах: возврат на последнюю жёлтую точку. Платформинг от первого лица легко раздражает; сон должен быть коротким (2–4 минуты) и прощающим.
- Можно ли во сне пострадать (рассудок), двигает ли он игровые часы.

> Собрано 16.10.2026 из итераций 1–8 обсуждения (история решений, исследование работы радиоведущих и разбор Dispatch — `Docs/CoreLoopDesign.md` и `Docs/CoreLoopResearch.md`). Заменяет мини-игру «Эфир» (02.3) в роли core loop. Все числа — стартовая точка для прототипа: проверяются только плейтестом.
>
> **Данные эфира** (заявки слушателей, позже — кассеты, реклама, объявления, звонки) ведутся в `Docs/Broadcast.xlsx`; пул случайных заявок для первых ночей уже набран.

**Идея.** Адаптация Dispatch: игрок закрывает заявки слушателей кассетами, как в Dispatch герои закрывают вызовы. У кассеты есть **вайбы** (аналог навыков героя), у заявки — скрытый запрос на вайбы. Сыгранная кассета уходит на перемотку (кулдаун). Давление создаёт очередь: элементов эфира приходит больше, чем хватает кассет и времени, и они конкурируют за один момент эфира.

**Время.** Режим эфира — за столом; пока игрок ходит по квартире, часы стоят. Один эфир (лента) ≈ **1 игровой час**, **2–4 эфира за ночь**. Эфир идёт **фиксированное реальное время**, одно число для всех эфиров: **для теста — 3 минуты**, потом, скорее всего, чуть больше. На экране бегут игровые часы. За чтение не наказываем: **пока открыто окно элемента (чтение или результат), время эфира и все таймеры стоят**; на основном экране они идут.

**Лента — дорожка «в пути»** (17.10.2026), как статус «В пути» у героев в Dispatch. Поставленный элемент появляется слева и едет направо; на ленте одновременно может ехать **несколько** элементов. Лента — это анимация выполнения уже сделанного выбора: всё, что в пути, доезжает. Давление создаёт не лента, а **таймеры входящих** и **нехватка кассет** (см. «Заявки»).

| Что едет | Время в пути | Особенность |
|---|---|---|
| Кассета (кассеты) по заявке | Одно для всех кассет, **5–10 с** (подбирается тестом) | По прибытии ждёт клика игрока за результатом |
| Реклама | **15 с** (тест) | Пока реклама в пути, **поставить в эфир ничего другого нельзя**; уже поставленное доезжает |
| Звонок в прямом эфире, объявление | ⚠️ решить по тестам | Вероятно, тот же порядок: клик → окно → «Поставить» |

**Экран (2D, за столом).**

| Зона | Что в ней |
|---|---|
| Слева — кассеты | Пул кассет на этот эфир. Во время эфира набор не меняется, меняется статус: активна / на перемотке. Кассета на перемотке — внизу колонки, некликабельна, на ней круглый анимированный таймер. Клик по активной — посмотреть вайбы |
| Центр — таймлайн эфира | Горизонтальная лента. Поставленный элемент появляется **слева** и едет **направо**; доехал до конца — можно смотреть результат |
| Под таймлайном — набор перков | Абилки с кулдауном (например, перемотка карандашом) |
| Справа — входящие | Динамический список: заявки, звонки в прямой эфир, реклама, объявления. Вокруг иконки каждого элемента — **круглый таймер**: не успел поработать с элементом — он пропадает |

**Как играется заявка** (решение автора, 17.10.2026, по образцу Dispatch):

![Набросок интерфейса эфира](BroadcastUI_Sketch.png)


1. На основном экране справа появляется заявка с круглым таймером.
2. Игрок кликает по заявке → открывается **окно заявки** (как окно вызова в Dispatch). Оно перекрывает ленту и правый список; колонка кассет слева и строка перков снизу остаются видны.
3. **Пока открыто окно заявки, таймеры стоят** — игрок спокойно читает. Окно можно закрыть в любой момент; если кассета не поставлена, таймер заявки продолжает идти.
4. Игрок назначает кассету (или несколько) и нажимает **«Поставить»** → иконка кассеты появляется слева на ленте эфира и едет направо.
5. Кассета доехала до конца ленты → игрок может **нажать на неё**: снова открывается окно заявки, теперь с **результатом проверки** (фигуры, процент, точка — см. «Проверка» ниже).
6. Игрок закрывает окно результата → кассета уходит **на перемотку** (вниз колонки, некликабельна, круглый таймер), затем возвращается в пул.
7. Не успел поработать с заявкой до конца её таймера — заявка пропадает и **считается провалом**.

**Элементы эфира.**

| Элемент | Что делает игрок | Что даёт |
|---|---|---|
| **Заявка слушателя + кассета(ы)** | Читает короткий текст с намёками на настроение (ключевые слова **жирным**), ставит одну или несколько кассет (до числа слотов заявки) | Проверка → баллы эфира, репутация фракции автора заявки |
| **Звонок в прямом эфире** | Небольшой диалог, выбор реплик | Сам выход на диалог и ответы → репутация фракций, баллы эфира |
| **Реклама** | Ставит рекламный блок | **Деньги**. Пока реклама в пути, ничего другого поставить нельзя — таймеры остальных входящих при этом идут |
| **Объявление** | Короткое объявление от ведущего (приходит заранее или сообщением во время эфира) | Сюжетные ветки, репутация фракций; на баллы эфира не влияет |

> Устарело (16.10.2026): «лента = 24 клетки по 2,5 игровой минуты», «песня — 2 клетки, реклама — 3, звонок — 3–4, объявление — 1». Лента больше не делится на клетки; вместо этого — время в пути (выше) и таймеры входящих. Длительности таймеров входящих и перемотки — подобрать тестом.

**Заявки.** У заявки есть автор (если он из фракции — заявка двигает её репутацию) и таймер ожидания: не успел — слушатель ушёл, это **провал** (уточнено 17.10.2026; раньше — «пропуск»). Вайбы нескольких кассет на одной заявке складываются. **Одна кассета никогда не даёт 100 %** (решение автора, 17.10.2026): у заявки хотя бы один вайб сильнее, чем у любой подходящей кассеты, включая странные, и профиль заявки не копирует кассету. Надёжность покупается второй кассетой ценой лишней перемотки.

**Слоты кассет (17.10.2026).** У каждой заявки есть **число слотов** — сколько кассет можно в неё поставить. Число зависит от уровня заявки: на сложные — 2–4 слота. Главная дилемма эфира: ставить **по одной кассете** и надеяться, что угадал вайбы и повезёт с проверкой, или **по несколько** для надёжности — тогда кассет может не хватить на остальные заявки. Таблица «уровень → слоты» — в `Broadcast.xlsx` (лист «Пороги»; описание — `Docs/Инструкция_по_заполнению_Broadcast.md`), колонка «Слотов кассет» в заявках считается сама.

**Стартовые числа для теста (17.10.2026, подбираются плейтестом).**

| Параметр | Значение |
|---|---|
| Длина эфира | 3 минуты реального времени |
| Время в пути: кассета / реклама | 5–10 с / 15 с |
| Появление новой заявки | раз в 10–15 с |
| Максимум элементов во входящих | 5 (лишнее ждёт) |
| Таймер заявки | ≈ 30 с |
| Перемотка кассеты (кулдаун) | ≈ 20 с (💡 предложение: при 4 кассетах и заявке раз в 10–15 с иначе ставить по две кассеты слишком безопасно) |
| Стартовые кассеты | К-01…К-04 из `Broadcast.xlsx` (лист «Кассеты»); К-05 — странная, по желанию |
| Баллы эфира | +1 за успех, 0 за провал |
| Зарплата | баллы × N (N — TBD) |

**Результат ждёт игрока (17.10.2026).** Кассета, доехавшая до конца ленты, **стоит там, пока игрок не кликнул на неё** за результатом, и только после закрытия окна результата уходит на перемотку. Это подталкивает смотреть результаты сразу: пока не посмотрел — кассета не возвращается, выбор меньше. Доехавшая кассета визуально показывает, что **ждёт клика** (подсветка, мигание, значок). В конце эфира непросмотренные результаты открываются один за другим.

**Вайбы** (черновик): **Тоска, Драйв, Нежность, Ностальгия, Протест** — пять, как пять навыков героя в Dispatch. Поле проверки — **пятиугольник** (17.10.2026).

**Число вайбов в заявке (17.10.2026).** В финальной игре в первой ночи допускается заявка с одним вайбом (обучение), со второй ночи — минимум два. **Для тестового билда — минимум два везде**, включая первую ночь: автору нужно проверить механику.

**Странные кассеты (17.10.2026).** «Странное» — не вайб, а **свойство кассеты**; в заявках его нет. Так Хтонь приходит в эфир как содержание и не ломает технику (01.1а).

- Странные кассеты **сильнее обычных** (большая сумма вайбов на том же уровне).
- Граница у них **красная** (у обычных — жёлтая); в окне результата их вклад в фигуру кассет закрашен красным.
- Точка остановилась в обычной части фигуры кассет — **успех**; в красной части — **успех и +1 Хтонь** (игрок сам выпустил Хтонь в эфир); вне фигуры — провал.
- Красная часть — то, что странные кассеты добавили к фигуре обычных: (фигура всех кассет ∩ фигура заявки) минус (фигура обычных кассет ∩ фигура заявки). Если на заявке только странная кассета, вся её фигура красная.
- Штрафные зоны (как красный ромб «избегать» в Dispatch) — возможный отдельный инструмент для заявок от Хтони; в первой ночи не нужен.

**Проверка — бинарная** (подошла / не подошла), по образцу Dispatch (17.10.2026).

*Как это видит игрок (решение автора):*

1. Игрок ставит кассету (или несколько) на заявку → короткая «загрузка» (кулдаун) → в центре экрана открывается окно результата.
2. Сначала показывается **фигура кассет** — многоугольник на радаре вайбов, построенный по сумме вайбов поставленных кассет.
3. Затем — **фигура заявки**, построенная по сложностям заявки. Обычно она больше фигуры кассет, но не всегда: зависит от того, насколько удачно игрок подобрал кассеты.
4. Внизу окна — **процент перекрытия** фигуры заявки фигурой кассет (целое число).
5. Из центра запускается точка, отскакивает от стенок фигуры заявки и постепенно замедляется. **Остановилась внутри фигуры кассет — успех, снаружи — провал.**

*Как это считается (предложение Claude, черновик под плейтест):*

- **Оси.** Пять вайбов равномерно по кругу (ось *i* под углом 90° + *i*·72°) в порядке: Тоска, Драйв, Нежность, Ностальгия, Протест (Протест соседствует с Тоской).
- **Вершина на оси** ставится на расстоянии **max(значение, b)** от центра, где **b = 0,2** — «подложка». Без неё фигура вырождается в отрезки нулевой площади, и процент не посчитать: так бывает не только у заявки с одним вайбом, но и у заявки с двумя **несоседними** вайбами (например, Тоска + Ностальгия) — площадь есть только в секторах между соседними осями. Поэтому подложка нужна при любом числе вайбов. b должна быть заметно меньше 1, иначе вайб со значением 1 засчитывается бесплатно.
- **Фигура кассет:** значение на оси = **сумма этого вайба у всех кассет**, поставленных на заявку.
- **Шанс** p = площадь(фигура кассет ∩ фигура заявки) / площадь(фигура заявки). На экран выводится round(100·p) %. Избыток вайбов кассеты за пределами фигуры заявки не штрафует.
- **Площадь пересечения** считается по секторам между соседними осями: в каждом секторе обе фигуры — треугольники с вершиной в центре, их пересечение находится отсечением одного треугольника другим (Sutherland–Hodgman); площади секторов складываются. Фигуры на радаре невыпуклые, поэтому общий алгоритм отсечения для выпуклых фигур к ним напрямую не применим — отсюда разбиение на сектора.
- **Исход и анимация.** Сначала бросок: успех с вероятностью p. Затем подбирается траектория точки: случайная начальная скорость из центра, отражения от стенок фигуры заявки, затухание; перебираются стартовые скорости, пока точка не остановится в нужной области (внутри фигуры кассет — при успехе, снаружи — при провале). Так процент на экране честно равен шансу, а движение выглядит физическим. При 100 % или 0 % перебор не нужен.

*Примеры расчёта (b = 0,2; заявки из `Broadcast.xlsx`):*

| Заявка | Кассета(ы) | Шанс |
|---|---|---|
| L-009, Тоска 3 + Нежность 1 | Тоска 3 + Нежность 1 (точное попадание) | 100 % |
| L-009 | Тоска 3 + Ностальгия 1 (почти) | 82 % |
| L-009 | Тоска 2 + Нежность 2 (слабее по главному вайбу) | 76 % |
| L-009 | Драйв 3 + Протест 1 (мимо) | 18 % |
| L-003, Протест 3 | Протест 2 + Драйв 2 | 70 % |
| L-024, Тоска 3 + Нежность 3 (уровень 2) | одна кассета Тоска 3 + Нежность 1 | 67 % |
| L-024 | две кассеты: (Тоска 3 + Нежность 1) + (Нежность 2 + Ностальгия 2) | 100 % |

*Ручки баланса:* подложка b (чем больше, тем щедрее «мимо»); площадь растёт квадратично от значения, поэтому сильный вайб весит заметно больше слабого.

> ⚠️ **Проверить на тесте (17.10.2026).** Если два вайба заявки стоят на **соседних** осях (например, Нежность + Ностальгия), кассета, попавшая только в один из них, получает мало: между ними на радаре большой треугольник. На стартовом наборе это «почти попадание» даёт 22–34 % при 18 % у совсем неподходящей кассеты — разница слабо ощутима. Альтернатива подложке: **прибавлять к каждой оси базу k** (вершина = значение + k) — фигуры становятся полными пятиугольниками, как у героев в Dispatch. При k = 0,5: точное попадание 100 %, почти — 40–52 %, мимо — 33 %. В тестовом билде стоит сделать способ (подложка или база) и его число настраиваемыми.

**Кассеты.**

- **Пул:** на старте 3–4 кассеты, затем 6, затем 8–10 (проверяется на плейтестах с учётом того, насколько тяжело работать с большим выбором). Больше лимита нельзя — можно заменить.
- **Вместо прокачки** — замена на более сильные добытые кассеты: ларёк, подарки «Гаража», вещи Серёги, сюжет.
- **Уровень кассеты** = сумма её вайбов (для баланса; игроку можно не показывать). Уровень 1 — сумма 4, ни один вайб не больше 3; уровень 2 — сумма 6, максимум 4; уровень 3 — сумма 8, максимум 5 (черновик).
- **Перемотка (кулдаун):** после проверки кассета уходит вниз списка, некликабельна, вокруг идёт полоска таймера; затем возвращается на место.

**Перемотка карандашом** — абилка с собственным кулдауном: быстрее возвращает кассету из перемотки (аналог перка «кофе» в Dispatch). Выполняется QTE-шкалой.

**Итоги эфира** (по образцу Dispatch: успешные / проваленные / пропущенные вызовы, мягкий штраф за пропуски, бонус за идеальную смену).

| Показатель | Откуда | Что делает |
|---|---|---|
| **Баллы эфира** | Выполненные заявки, удачные звонки; пропущенные элементы дают небольшой минус | После эфира Викторыч комментирует результат и выписывает зарплату |
| **Деньги** | Зарплата за баллы + реклама; премия за идеальный эфир | Ларёк (01.1а) |
| **Репутация фракций** | Заявки, звонки, объявления; пропущенное фракционное — минус | Шкалы 01.6 |

**QTE-шкалы.** Визуальный язык — как мини-игры рыбалки в Dredge: разновидности шкал (дуги, кольца, спираль), где одной кнопкой нужно нажать, когда бегунок в зелёной зоне. Сложность — через форму шкалы (например, редкая кассета перематывается по шкале с узкими зонами). Сейчас точно используется для перемотки карандашом; кандидаты — подводка, склейка, анимация проверки.

> ⚠️ **По каждой шкале уточнять реализацию у автора.** Шкалы отличаются не только формой, но и немного механикой (хотя везде нажимается одна кнопка вовремя). Не реализовывать новую шкалу по одному описанию формы.

**«Провода»** (бывший «Эфир» из демо, 02.3) — пока назначены на **ремонт** (бытовая поломка до первой ленты); можно пересмотреть.

**Открытое:** падение вайба (дебафф кассеты) — нужно логичное объяснение в радиоэфире; вариант — «заезженность» от частого проигрывания вместо провала. Какие QTE кроме перемотки брать (подводка, сигналы точного времени, «пятый дозвонившийся», склейка). Схема «Две деки» — под вопросом.

## 07 — ART / ATMOSPHERE

### 07.1. Основная цель

Игроку должно быть приятно просто находиться на радиоточке. Это важнее попытки постоянно его пугать.

### 07.2. Уют

Уют создаётся через тёплый свет, небольшие локальные источники света, дождь или снег за окном, музыку, мягкий гул техники, чай, обжитое рабочее место, интерактивные мелочи и кошку.

**Что сделано в сцене:** приглушённый вечерний свет по всей квартире (источники расставлены по комнатам, свет торшера отдельно, ближе к белому, чем к жёлтому), совсем лёгкий туман (Exponential, плотность 0,03), летающие частицы пыли в воздухе (объект `DustMotes`) и небольшая виньетка на камере игрока при ходьбе по квартире. Где всё это редактировать — `Docs/Памятка разработчику.md`.

### 07.3. Мистика

Главный принцип — «обычная сцена + одна неправильная деталь». Не злоупотреблять красным светом, глитчами, скримерами, кровью и демоническими эффектами. Лучше использовать звонящий без подключения телефон, изменившуюся запись, предмет не на своём месте, собственный голос по радио, неправильное время на часах или странную реакцию кошки.

**Приёмы, заложенные в сценарий:** шифр в объявлениях бабки Зины; Алиса, которая во снах обретает цвет по ночам; шипящее радио, на котором вдруг говорит человек; шаги по лестнице, когда на площадке никого нет; кошка, которая кашляет перед «мяу».

### 07.4. Эпоха

Визуальный образ строится на сочетании советского оборудования, техники 90-х и первых элементов начала 2000-х. Помещение не должно выглядеть как музей СССР или заброшенная хоррор-локация.

### 07.5. Видео

Видео в игре: фон главного меню (`V_MainMenu`), вступительный ролик перед игрой (`Intro`), сон Алисы в ночи 1 (`Dream1`), анимация бабки Зины как собеседника (прозрачный фон; зелёный фон вырезается заранее при подготовке файла).

## 08 — ТЕХНИЧЕСКАЯ СТРУКТУРА

Минимальный набор систем из исходного плана и их реальные реализации:

| Система по плану | Что реально в проекте |
|---|---|
| InteractionManager | `PlayerInteractor` (прицел, наведение, нажатие) + базовый `Interactable` |
| TimeManager | `TimeManager`: часы смены 00:00–06:00, номер ночи, сквозной счёт минут |
| BroadcastManager | `MinigameHost` (запуск эфиров по часам) + `NightSchedule` / `ScheduleRunner` (разговоры по отметкам) |
| DialogueManager | Yarn Spinner + `DialogueController` + `RadioVariableStorage` (переменные диалога = состояние игры) |
| PhoneManager | `PhoneRinger` (звонки по часам и перезвоны) + `Phone.yarn` |
| RadioFrequencyManager | `RadioTuner`, `RadioReceiver`, `RadioStationList` |
| CassetteManager | `TapeDeck` (кассетник по имени: микшер, плеер, эфир) |
| AudioRoutingManager | не реализовано |
| EventManager | `GameTimeMark` + `TimedEvent` + `TaskAtTime` + `ActivateAtTime` + `DoorKnocker` + `StoryBeats` |

| SaveManager | не реализовано |

Дополнительно: `SleepSequence` (смена ночей), `EntranceDoor`/`DoorKnocker`/`DoorVisitorView` (гости), `InspectableItem` (3D просмотр), `CombinationLock`, `ScreenFocus` и `ComputerDesktop` (компьютер), `TaskHud`, `StoryStatsHud`, `StatEdgeEnding` (концовки по краям шкал, выключены).

### 08.1. Event Structure

Событие описывается отметкой на игровых часах и узлом диалога; остальное решает сам узел. В коде это:

- **`GameTimeMark`** — «ЧЧ:ММ» или «ЧЧ:ММ:НН» плюс задержка в реальных секундах после отметки. Событие без привязки к часам не допускается.
- **`TaskAtTime`** — ставит задачу в отметку, если сюжет не поставил её раньше.
- **`ActivateAtTime`** — включает предмет в отметку (банка Зины).
- **Условия и флаги** (`RequiredFlags`, `Conditions`, `ResultFlags` исходной схемы) записываются **внутри узла Yarn**, а не в таблице, чтобы логика ночи не расползалась по двум местам.
- **Для отладки** каждое новое событие обязано: (1) отменять себя при переводе часов вперёд, (2) быть внесено в `Data/Tasks.asset`, если ставит задачу, (3) быть внесено в `Data/StoryBeats.asset`, если это сюжетный шаг (время + флаги завершения).

### 08.2. Naming Convention

Использовать единый формат: `STORY_FOUND_SERGEY_KEYS`, `NPC_MISHA_TRUST`, `KNOW_ACCIDENT_DATE`, `ACTION_AIRED_WARNING`, `SECRET_CAT_HINT_01`, `TASK_…`. Параметры сюжета названы по-английски без префикса: `Crime`, `Cult`, `GirlFriend`, `CatHunger`.

### 08.3. Стиль и приёмы

Код и документация проекта пишутся на русском и объясняют, «почему», а не «что». Интерфейс строится кодом, а не расставляется руками; ссылки на `GameSession` берутся в `Start`, а не в `Awake`. Новый диалог — это `.yarn` файл в `Assets/_Project/Yarn`, объявления переменных — в начале файла ночи.

### 08.4. Инструменты разработки

Команда работает с ИИ-помощниками (Claude Code и Codex) через MCP. Подробные записи сессий для передачи работы лежат в `Docs/AI/`.

### 08.5. Данные эфира: Broadcast.xlsx → Unity через CSV — 🟡 реализовано для теста

> 17.10.2026: загрузчик `BroadcastData` читает `Requests.csv`, `Cassettes.csv`, `Ads.csv` по правилам ниже. Первые CSV выгружены скриптом из таблицы; после правки таблицы листы нужно пересохранить из Excel поверх (`Reference.csv` и `StoryRequests.csv` пока не читаются).

> 17.10.2026. Решение автора: переносить через **CSV** (надёжнее, чем отдельный импортёр .xlsx). Таблицу будут править часто, поэтому ниже — правила, чтобы перенос не ломался.

- **Источник правды — `Docs/Broadcast.xlsx`.** CSV — производная копия, руками не правится.
- **Один лист — один CSV.** Excel сохраняет в CSV только активный лист: «Заявки», «Кассеты», «Реклама», «Сложность» экспортируются по отдельности (в тестовой сборке: `Requests.csv`, `Cassettes.csv`, `Ads.csv`, `Difficulty.csv`; «Сюжетные заявки» — `StoryRequests.csv`, когда понадобятся). Лист «Пороги» в Unity не выгружается: он нужен только формулам Excel. Правила заполнения — `Docs/Инструкция_по_заполнению_Broadcast.md`.
- **Куда:** `Assets/_Project/Data/Broadcast/*.csv` — Unity видит их как `TextAsset`, они попадают в сборку.
- **Формат при сохранении:** «CSV UTF-8». ⚠️ Русский Excel по умолчанию ставит разделителем **точку с запятой**, а обычный «CSV» сохраняет в кодировке Windows-1251. Поэтому чтение CSV в игре: (1) определяет разделитель сам (`;` или `,`) по строке заголовков; (2) читает UTF-8 с BOM и без; (3) понимает кавычки — в текстах заявок есть запятые.
- **Колонки ищутся по названию заголовка**, а не по номеру: добавление или перестановка колонок не ломает загрузку. Формулы Excel выгружает в CSV уже посчитанными значениями.
- **Проверки при загрузке** с отчётом в консоль: повторяющиеся ID, «ошибка» уровня, меньше двух вайбов, фракция не из списка, пустой текст, «не по норме» у кассет.
- **Строки «EX-…» пропускаются.** Разметка `**слово**` превращается в `<b>слово</b>` для TextMeshPro.

## 09 — PRODUCTION / SCOPE

### 09.1. MVP

Для первой рабочей версии достаточно одной студии, одной ночи, микшера, кассетника, телефона, эфирного расписания, двух обычных звонков, одного сюжетного звонка, одной странной частоты, одной небольшой загадки и нескольких бытовых взаимодействий. **Выполнено и превышено:** игра собрана как вертикальный срез из трёх ночей, реализованы две.

### 09.2. Vertical Slice

Цель — 20–30 минут полноценной первой ночи. Vertical slice должен доказать две вещи: интересно ли работать на радио и приятно ли просто находиться в радиоточке между событиями. **Состояние:** ночь 1 реализована от звонка до сна, ночь 2 собрана целиком. Windows-сборка делалась несколько раз для отправки на модерацию.

### 09.2а. Рамки полной версии

Решение автора от 12.10.2026: ориентируемся на **7 ночей**, число ночей будет подстраиваться под сюжет и плейтесты (допустимо сократить, см. cut list 09.4). Команда проекта — несколько человек.

**Референс по длительности — Static Dread: The Lighthouse** (первая часть, 15 ночей): по сторонним оценкам, основной сюжет проходится примерно за 6–6,5 часа (HowLongToBeat, GG.deals). Для сравнения: вторая часть, The Submarine, — около 4 часов.

**Длина ночи (решение от 12.10.2026, вопрос 9).** Ночь — это законченная смысловая часть сюжета и одновременно точка сохранения и отдыха для игрока, поэтому ночи не растягиваем. Ориентир — средняя ночь Static Dread: ~6,3 часа на 15 ночей ≈ **25 минут** (оценка делением, отдельного замера по ночам нет). Цель — **20–30 минут на ночь**, как у нынешней ночи 1. При 7 ночах это ~2,5–3,5 часа игры; если понадобится длиннее, добавляем ночи, а не растягиваем каждую.

### Приём чужого Pull Request — для Нила

Главное отличие от обычного проекта: дифф Unity-сцены глазами не читается. `.unity` и `.prefab` — это YAML на тысячи строк, где перемещение объекта выглядит как смена чисел в блоке с ID. Поэтому настоящее ревью здесь — это выкачать ветку и открыть её в Unity, а не смотреть на GitHub.

**1. Посмотреть, что пришло**

```powershell
gh pr list
gh pr view 1
```

Покажет описание, автора, ветку и статус. Список изменённых файлов:

```powershell
gh pr diff 1 --name-only
```

Если в списке только `.cs` — можно читать текстом: `gh pr diff 1`. Если есть `.unity`, `.prefab`, `.asset` — переходи к следующему шагу.

**2. Проверить по-настоящему**

```powershell
git stash
gh pr checkout 1
```

`git stash` прячет твои незакоммиченные правки, чтобы переключение ветки их не задело. Если у тебя всё закоммичено — не нужен.

Теперь открой проект в Unity и посмотри руками: запускается ли сцена, нет ли ошибок в консоли, работает ли то, что человек заявил в описании PR.

Вернуться к себе:

```powershell
git checkout dev-nil
git stash pop
```

`stash pop` возвращает спрятанные правки. Если ничего не прятал — пропусти.

**3. Одобрить или вернуть на доработку**

```powershell
gh pr review 1 --approve -b "Проверил в редакторе, работает"
gh pr review 1 --request-changes -b "В консоли ошибка компиляции при открытии сцены"
gh pr comment 1 -b "Посмотри ещё скорость ходьбы, кажется быстровато"
```

**4. Влить**

```powershell
gh pr merge 1 --merge --delete-branch=false
```

Именно `--merge`, не `--squash`. Это важно в нашей схеме: ветки `dev-nikolas` и `dev-danya` живут постоянно, их не удаляют после вливания. Если сделать squash, история ветки и история `main` разойдутся — git перестанет видеть, что эти коммиты уже влиты, и при следующем PR тот же код приедет повторно, уже с конфликтами.

`--delete-branch=false` обязателен по той же причине — ветка человека должна остаться.

**5. Если GitHub пишет, что слить нельзя**

Значит конфликт: кто-то изменил те же строки в `main`. Чинить должен автор PR, не ты. Верни ему — он делает:

```powershell
git checkout dev-nikolas
git pull origin main
git push origin dev-nikolas
```

PR обновится сам, ничего пересоздавать не нужно. Причина такого порядка: у него проект открыт в Unity и он знает, какие из его изменений в сцене нужны. Ты этого не знаешь и разрешишь конфликт наугад.

**6. После вливания**

Скажи в чат, чтобы остальные подтянули `main` — иначе они продолжат работать на устаревшей базе и следующий конфликт будет больше:

```powershell
git checkout dev-danya
git pull origin main
```

И себе тоже:

```powershell
git checkout dev-nil
git pull origin main
```

**Через браузер.** Диффы `.cs` и обсуждение удобнее в вебе: https://github.com/nil-games/Radio/pulls — кнопка **Files changed** → зелёная **Review changes** → **Approve** → **Merge pull request**. В выпадающем списке выбирай **Create a merge commit**, не Squash — по причине из пункта 4. Проверку в Unity это всё равно не заменяет.

### 11.2. Как добавить новую модель интерактивного объекта в сцену

1. На объект модели: **Add Component → Радио → 3D просмотр**.
2. Добавь коллайдер, например **Box Collider**, иначе на предмет не навестись.
3. Если нужна обводка при наведении, как у Алёнки, добавь **OutlineHighlighter**.
4. В поле **Font** поставь `LiberationSans SDF RU`, иначе подсказка внизу экрана не отобразится.
5. Запусти Play и посмотри, как модель ложится в руки. Если она боком или вверх ногами, подбери поле **Hold Euler**: у Алёнки там `(0, 90, 180)`.
