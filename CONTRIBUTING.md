# Как работать с репозиторием

Проект: Unity **6000.4.1f1**, 3D URP. Все примеры команд — для **PowerShell** (в нём `&&` не работает, команды пишем по одной).

---

## Роли

| Кто | Права |
|---|---|
| **Nil** — ведущий разработчик, владелец репозитория | Пушит в `main` напрямую. Ревьюит и одобряет вливание чужих веток в `main`. |
| **Nikolass**, **Danya** | Работают в своих ветках. В `main` попадают только через Pull Request, который одобряет Nil. |

Ветки:

| Участник | Ветка |
|---|---|
| Nikolass | `dev-nikolas` |
| Danya | `dev-danya` |
| Nil | `dev-nil` |

`main` — всегда рабочая сборка. Если в `main` что-то не запускается, это чрезвычайная ситуация: чиним первым делом.

## Разовая настройка (один раз на машине)

### 1. Клонировать

```powershell
git clone <URL репозитория>
cd Radio
```

### 2. Включить Git LFS

```powershell
git lfs install
```

Без этого арт и звук скачаются как текстовые заглушки вместо файлов.

### 3. Представиться гиту

```powershell
git config --global user.name "Твоё Имя"
git config --global user.email "твоя@почта"
```

### 4. Подключить Unity-мерджер сцен — обязательно

В `.gitattributes` прописано, что `.unity`, `.prefab`, `.asset`, `.mat`, `.anim`, `.controller` мержатся через UnityYAMLMerge. Но git не знает, где лежит эта программа, пока ей не скажешь. **Если этот шаг пропустить, git при конфликте покромсает сцену построчно и она перестанет открываться.**

```powershell
git config --global merge.unityyamlmerge.name "Unity SmartMerge"
git config --global merge.unityyamlmerge.driver '"C:/Program Files/Unity/Hub/Editor/6000.4.1f1/Editor/Data/Tools/UnityYAMLMerge.exe" merge -p "$BASE" "$REMOTE" "$LOCAL" "$MERGED"'
git config --global merge.unityyamlmerge.recursive binary
```

Если Unity установлена не по умолчанию — подставь свой путь до `UnityYAMLMerge.exe`.

### 5. Перейти на свою ветку

Ветки уже созданы на сервере, создавать заново не нужно:

```powershell
git checkout dev-nikolas
```

### 6. Открыть проект

В Unity Hub: **Add → Add project from disk** → папка `Radio`. Новый проект через «New project» создавать **не нужно** — репозиторий уже является проектом.

## Ежедневный цикл

### Утром: забрать свежий `main`

Делай это каждый раз перед началом работы. Чем реже подтягиваешь — тем больнее конфликты.

```powershell
git checkout main
git pull origin main
git checkout dev-nikolas
git merge main
```

Если Unity открыта — она переимпортирует изменения, дай ей закончить.

### В течение дня: коммить и пушить своё

```powershell
git add -A
git commit -m "feat: добавил систему управления"
git push origin dev-nikolas
```

Пушь свою ветку **часто** — хоть каждый час. Это твоя страховка: если Unity уронит проект или сломается диск, работа уже на сервере.

Формат сообщений:

| Префикс | Когда |
|---|---|
| `feat:` | новая функциональность |
| `fix:` | починка бага |
| `art:` | графика, звук, ассеты |
| `refactor:` | переписал без смены поведения |
| `chore:` | настройки проекта, мелочи |

## Как попасть в `main`

### Nikolass и Danya — через Pull Request

1. Убедись, что твоя ветка запушена и в неё влит свежий `main` (см. «Утром» выше) — конфликты разрешаешь **у себя**, а не в PR.
2. Проверь, что проект открывается и сцена запускается. Не работающий код в PR не отправляем.
3. Открой PR на GitHub: вкладка **Pull requests → New pull request**, base `main` ← compare `dev-nikolas`. Защита ветки не даст влить PR без одобрения — это нормально, так и задумано.
4. В описании — коротко, что сделано и что нужно проверить.
5. Напиши Nil в чат, что PR готов.
6. Nil ревьюит и мержит. Сам кнопку «Merge» не нажимай.

После того как PR влит:

```powershell
git checkout main
git pull origin main
git checkout dev-nikolas
git merge main
```

### Nil — напрямую

```powershell
git checkout main
git pull origin main
git merge dev-nil
git push origin main
git checkout dev-nil
```

### Nil — принять чужой PR

На GitHub в PR: посмотреть вкладку **Files changed**, затем **Merge pull request**. Если в PR конфликты — не решай их сам, верни автору с просьбой влить `main` к себе и запушить заново.

Если хочешь проверить чужую ветку локально перед мержем:

```powershell
git fetch origin
git checkout dev-nikolas
```

Посмотреть в Unity, потом вернуться к себе: `git checkout dev-nil`.

## Сцены и префабы — главный источник боли

> **Перед правкой любого `.unity`-файла предупреди команду в чате.**

Сцена — это один большой файл. Если двое правят её одновременно, git не сможет аккуратно объединить правки, даже с UnityYAMLMerge. Лечится только договорённостями:

- Один человек — одна сцена за раз.
- Всё, что можно вынести в **префаб**, выноси в префаб. Префабы конфликтуют реже, потому что мелкие.
- Закончил со сценой — сразу коммить и пушь, не держи её занятой полдня.

**Обязательная настройка, она уже в репозитории и приедет сама:** `Edit → Project Settings → Editor → Asset Serialization → Mode: Force Text`. Проверь, что стоит именно так — без этого сцены бинарные и командная работа невозможна.

## Что не коммитим

`.gitignore` уже настроен и отсекает главное: `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `Build/`, `*.csproj`, `*.sln`. Эти папки генерируются Unity у каждого свои.

Если видишь их в `git status` — что-то не так, напиши в чат, а не коммить «на всякий случай». Особенно `Library/`: это сотня с лишним мегабайт, которая намертво осядет в истории.

Арт и звук (`.png`, `.jpg`, `.psd`, `.fbx`, `.wav`, `.mp3`, `.ogg`, `.tga`, `.mp4`) автоматически уходят в LFS — отдельно ничего делать не нужно, просто клади файлы в `Assets/_Project/Art` или `Assets/_Project/Audio`.

## Если что-то сломалось

**«Я накоммитил ерунду, хочу откатить последний коммит, но сохранить файлы»**

```powershell
git reset --soft HEAD~1
```

**«Хочу выбросить все свои несохранённые правки в файле»**

```powershell
git checkout -- Assets/_Project/Scripts/Player.cs
```

**«Конфликт в сцене, ничего не понимаю»**

Не пытайся править YAML руками. Возьми одну из версий целиком:

```powershell
git checkout --ours Assets/_Project/Scenes/Main.unity
git add Assets/_Project/Scenes/Main.unity
```

`--ours` — твоя версия, `--theirs` — та, что приехала. Потерянные правки придётся повторить в Unity вручную. Затем сообщи в чат, чтобы второй человек знал, что его изменения в сцене не доехали.

**«Push отклонён: rejected, non-fast-forward»**

Кто-то запушил в твою ветку раньше тебя. Подтяни и повтори:

```powershell
git pull origin dev-nikolas
git push origin dev-nikolas
```

**Всё совсем плохо и горит дедлайн** — скопируй папку `Assets/_Project` куда-нибудь на диск, склонируй репозиторий заново в чистое место и перенеси файлы руками. Это некрасиво, но за час до сдачи работает.

## Структура проекта

```
Assets/
├── _Project/        — всё наше
│   ├── Scripts/     — C# код
│   ├── Scenes/      — сцены
│   ├── Prefabs/     — префабы
│   ├── Art/         — спрайты, текстуры, модели
│   ├── Audio/       — звуки и музыка
│   └── UI/          — UI-элементы
└── Settings/        — URP-ассеты, не трогаем без нужды
```

Всё своё кладём в `_Project`. Импортированные из Asset Store пакеты ложатся в `Assets/` рядом — так сразу видно, где наше, а где чужое.
