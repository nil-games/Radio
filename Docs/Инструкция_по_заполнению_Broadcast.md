Источник правды для этих чисел — лист «Пороги»; таблицы ниже показывают их значения на 17.10.2026 и объясняют смысл. Поменяли число на листе — поправьте и таблицу здесь.

> Источник правил механики — `Docs/GDD.md`, раздел 02.22 (эфир за столом). Числа сложности и пороги — стартовые, проверяются плейтестом.

## 1. Что это и листы

`Broadcast.xlsx` — вся рабочая таблица мини-игры «Эфир» (симуляция работы радиоведущего, GDD 02.22). Перенос в Unity — экспорт каждого листа в CSV (GDD 08.5).

| Лист | Что в нём |
|---|---|
| **Заявки** | Большой пул независимых случайных заявок: игра берёт их наугад. Заполнен пулом для первых ночей (L-001…) |
| **Сюжетные заявки** | Заявки сюжетных персонажей с конкретным временем появления: ночь, эфир (лента), время. Строка «EX-S01» (серый курсив) — пример формата; удалите её, когда появятся настоящие сюжетные заявки |
| **Сюжетные элементы** | Звонки в прямой эфир и объявления с узлом Yarn (раздел 1а ниже) |
| **Кассеты** | Пул кассет |
| **Реклама** | Рекламные блоки |
| **Сложность** | Параметры каждого эфира по ночам: поток элементов, пул кассет, уровни заявок |
| **Пороги** | Числа для формул (раздел 4 ниже) |

Одна строка = одна заявка. У одного слушателя может быть несколько заявок — тогда несколько строк с одним именем.

## 1а. Лист «Сюжетные элементы» (18.10.2026)

Звонок в прямой эфир или объявление, которое ведущий читает в эфир. В отличие от заявки, у элемента нет кассет и проверки: игрок открывает его, идёт разговор (узел Yarn), после этого элемент едет по ленте и уходит. Экспорт — `Assets/_Project/Data/Broadcast/StoryElements.csv`.

| Колонка | Что писать |
|---|---|
| ID | `SE-N<ночь>-<номер>` |
| Ночь, Эфир | В каком эфире какой ночи приходит (номер эфира в ночи: 1, 2, 3…) |
| Появление, с | На какой секунде эфира появляется во входящих |
| Тип | «Звонок» или «Объявление» — подпись карточки |
| Заголовок | Что видно на карточке во входящих |
| Узел Yarn | Узел разговора; в нём `<<broadcast_skip>>` — «не ставить»: элемент остаётся во входящих до конца ожидания |
| Условие | Флаги мира через «;», все должны быть истинны; «!» перед флагом — ложен. Пусто — приходит всегда. Пример: `ACTION_ZINA_PROMISED` |
| Ожидание, с / Время в пути, с | Сколько ждёт во входящих и сколько едет по ленте после разговора; пусто — общие значения из `BroadcastSettings` |
| Файл сценария, Примечание | Для людей, игра не читает |

Сюжетный элемент приходит сверх лимита входящих. Не успели открыть — пропуск в сводке эфира.

## 2. Правила заполнения заявок

### Только для листа «Заявки»

1. Слушатель **не** просит конкретную кассету или песню по названию. Он описывает ситуацию и настроение; подходящая кассета — выбор игрока.
2. Заявка независима: **не** указываем, что событие повторится, запустит другое или зависит от предыдущей заявки. Никаких цепочек и условий появления.
3. Результат (при успехе и при провале) — только простые изменения: баллы эфира, деньги, репутация фракции / шкала. Флагов, запускающих другие события, не ставим.

### Только для листа «Сюжетные заявки»

Действуют общие правила 4–13 ниже. Отличия: обязательно указывать **Ночь**, **Эфир** (номер ленты) и **Время появления**; можно указывать сюжетные последствия и флаги (колонка «Сюжетные последствия»); цепочки допустимы.

### Общие правила для обоих листов

4. **Голос слушателя.** Текст заявки пишется строго по колонке «Характер и речь»: лексика, обращения, словечки, темп, манера. Проверка перед сдачей: в тексте минимум **два характерных приёма** из этой колонки (обращение, присказка, оговорка, манера обрывать фразу и т. п.). Заявки разных слушателей не должны звучать одинаково.
5. **«Характер и речь»** — короткая запись (1–2 фразы): возраст, темперамент, лексика, обращения, словечки. Это основа для правила 4.
6. Заявка — **около абзаца** (3–6 предложений). Слова-намёки на вайбы выделяем `**двойными звёздочками**` (в игре они будут жирными).
7. Слова-намёки можно и нужно придумывать новые: список в разделе 3 — только примеры, не ограничение.
8. **Сложность** задаётся числами по вайбам (0–10; 0 = вайб не проверяется). Вайбы нескольких кассет **суммируются**: сложность — порог для суммы. Вайб одной кассеты 1-го уровня не больше 3.
9. **Уровень** считается сам и равен **большему из двух**: (а) уровня по сумме вайбов, (б) уровня по числу задействованных вайбов (вайбов > 0). Один–два вайба — уровни 1–2; три вайба — не ниже 3; четыре вайба — только 5 (под конец игры); пять и больше — «ошибка». Пороги — раздел 4. На ранних ночах берём заявки низких уровней, на поздних — выше.
10. **Число вайбов.** В финальной игре: в первой ночи допускается заявка с одним вайбом (обучение), со второй ночи — минимум 2 вайба. **Для тестового билда — минимум 2 вайба везде**, включая первую ночь (пул L-001…L-025 сделан так). Одновайбовые заявки и заявки на «несоседние» вайбы считаются за счёт подложки b (GDD 02.22).
11. **«Странное»** — не вайб, а свойство кассеты (GDD 02.22). В заявках его нет; странность может звучать в атмосфере текста заявки, но не выделяется как намёк.
12. **Слоты кассет** — сколько кассет можно поставить в заявку; считается само по уровню (раздел 4). Сейчас: уровни 1–2 → 2 слота, 3–4 → 3, 5 → 4. Уровню 1 дано 2 слота, чтобы в тестовом билде проверить дилемму «одна кассета или несколько»; позже, возможно, станет 1.
13. **Ни одна кассета не даёт 100 %.** У заявки должен быть хотя бы один вайб сильнее, чем у любой подходящей кассеты (включая странные), и профиль заявки не копирует кассету. Тогда одна кассета даёт меньше 100 %, а надёжность покупается второй кассетой ценой лишней перемотки. Проверять по листу «Кассеты»: если все ненулевые вайбы заявки не больше, чем у какой-то одной кассеты, — заявка закрывается ею на 100 %, усилить главный вайб.

### Колонки

| Колонка | Что писать |
|---|---|
| ID | Уникальный номер (L-001…; для сюжетных S-001…) |
| Слушатель / Персонаж | Имя; сюжетный — как в таблице состава (`Docs/Персонажи.md`, 01.2а) |
| Фракция | Из списка: Нет, Гараж, Политех, Бандиты, Апофения, Хтонь |
| Тоска … Протест | Сложность проверки по вайбу |
| Сумма вайбов, Вайбов, Уровень, Слотов кассет | **Формулы, не редактируйте** |
| При успехе / При провале: текст | Что слушатель говорит в ответ |
| При успехе / При провале: результат | См. правило 3 |
| Ночи (лист «Заявки») | С какой ночи заявка может появляться (например, 3–7) |
| Эфир (лист «Сюжетные заявки») | Номер ленты в ночи, 1–4 |

### Уровень заявки по сумме вайбов

| Уровень | Сумма вайбов от | Ориентир: ночи (💡 предложение) |
|---|---|---|
| 1 | 1 | 1–2 |
| 2 | 5 | 2–4 |
| 3 | 7 | 4–5 |
| 4 | 9 | 5–6 |
| 5 | 12 | 6–7 |

### Уровень заявки по числу вайбов (вайбов > 0)

| Минимальный уровень | Вайбов в заявке от | Пояснение |
|---|---|---|
| 1 | 1 | 1–2 вайба: уровни 1–2 |
| 3 | 3 | 3 вайба: не ниже уровня 3 |
| 5 | 4 | 4 вайба: только уровень 5, под конец игры |

**Уровень заявки = большее из двух** таблиц выше. Пять вайбов и больше — «ошибка». Ориентир по сумме: вайбы кассет уровня 1 = 4, уровня 2 = 6, уровня 3 = 8 (GDD 02.22); заявка может требовать больше, чем даёт одна кассета, — тогда нужно несколько кассет.

| 2 | 2 | |
| 3 | 3 | |

### Нормы кассет по уровню (GDD 02.22)

## 5. Итоги эфира — как считает игра (тестовая сборка, 17.10.2026)

Сводка открывается, когда время эфира вышло и всё, что было в пути, доехало; непросмотренные результаты кассет перед этим открываются по очереди.

### Что случилось с заявкой

| Исход | Когда | Что засчитывается |
|---|---|---|
| **Подошло** | Кассеты поставлены, точка остановилась внутри фигуры кассет | Колонка «При успехе: результат» |
| **Не подошло** | Кассеты поставлены, точка остановилась вне фигуры кассет | Колонка «При провале: результат» |
| **Слушатель не дождался** | Заявку так и не поставили: кончилось её ожидание или кончился эфир | Это провал; результат заявки не засчитывается вовсе |

### Из чего складываются числа

- **Баллы эфира** — число перед словом «балл» в колонке результата заявки: «+1 балл эфира» → +1, «+2 балла эфира» → +2, «0 баллов эфира» → 0. Провалы и «не дождался» баллов не отнимают.
- **Деньги** — сумма колонки «Деньги» у каждой рекламы, которая доехала до конца ленты. Реклама, которую не поставили, денег не даёт и попадает в «Реклама не поставлена».
- **Хтонь +1** — за каждую заявку, где точка остановилась в красной части фигуры (успех за счёт странной кассеты).
- **Последствия** — всё остальное из колонки результата («+1 «Гараж»», «+1 к Криминалу») и из колонки «Последствия» рекламы. Пока только перечисляются в сводке; со шкалами сюжета, деньгами и зарплатой не связаны (напоминание в GDD 02.22 и 09.7).
- **Идеальный эфир** — хотя бы один успех и ни одного провала, «не дождался» и непоставленной рекламы. Пока только надпись в сводке.

### Чего пока нет (по GDD 02.22)

Минус к баллам за пропущенные элементы; зарплата от Викторыча (баллы × N); премия за идеальный эфир; репутация фракций и шкалы сюжета; деньги в ларёк.
